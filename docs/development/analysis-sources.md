# 分析工作区来源范围

本工作包的服务端范围模型、读取链路及来源选择界面已接通，历史收据使用当时的1.8.18版本。当前开发版本及候选状态见[实施进度](improvement-progress.md#接续入口)；接口和隔离浏览器测试不替代桌面人工验收。

## 声明式规则和源语义

`internal/sourceview`集中维护可保存的筛选/排序、显隐设置及`Scope`版本1。`workbook.FilterRule/SortKey/AxisViewSettings`等通过类型别名沿用它们，规范化及区间覆盖算法只有一份；运行时索引、行序、投影和源布局仍由workbook拥有。布局v6、`XLIDX009`、`ELNROW02`及`ELRICH01`不变，没有新增格式名单或生产依赖。

单表查询的`source`是`wb:<Sheet>`或`scratch:<ID>`。空`sourceScope`保持原来完整单表语义；有范围只用于原始工作表，指纹必须匹配。联合来源使用独立的`append:<摘要>`及完整声明定义，拥有者可以持有多来源快照；其`sourceScope`为空不代表无范围或完整单表，见[多表追加](table-composition.md)。

| 范围 | 固定集合和顺序 |
| --- | --- |
| 完整源表 | 既有索引记录，按源顺序，不受本机显隐影响 |
| `filtered` | 成功筛选的完整行序，包含手动隐藏的匹配行；不加入未匹配冻结行 |
| `visible` | 同一显隐状态的可见冻结源前缀及正文；无筛选时保留真实空白地址，范围截至已用源行 |
| `selection` | 源坐标与可视端点成对校验的画面选区，含可见冻结前缀；保留原列号 |

表头及其之前的源行不参与分析，按源行号判断，不把排序后的第N个结果当作源表头。选区可包含已用区域以外的真实空白地址；字段仍受现有前256列限制，越界拒绝而非截断。范围内空白列使用原列标识及空值，不搬入邻列的值。字段预览至多读取8条范围记录，不检测整表日期。

`Scope`只保存指纹、范围类型、成功筛选规则、显隐设置、有效冻结边界及选区源/可视端点；不保存临时ID、整表数据或行号向量。数值、文本金额规则、前导零、类型、公式缺缓存和源坐标沿用公共读取。新的范围和请求拒绝未知字段、未知版本、超限及不一致端点；失效ID不退回完整来源。

## 快照与任务归属

`analysisSourceSnapshot`以引用计数持有`selectionSnapshot`及`selectionRowPlan`，复用RowOrder、显隐投影、源固定和流式行引用。不复制匹配行数组，不给隐藏行建立map。表头排除计数选择较小的源索引前缀或显示片段，只查看索引，不预扫描单元格。

每页最多8个来源拥有者，容量由formats维护。字段请求、任务及导出分别取得引用；池淘汰、清除、原筛选/显隐视图清除及App关闭，不提前回收其他消费者。完成分析保留范围到任务淘汰，以支持下钻和异常；失败或排队取消释放任务引用。最后引用释放投影、行序及来源固定。

完整及有范围来源共用`scanWorkbookAnalysisRows`，沿严格`SourceRowReference`读取，不改写源值，也不启用富文本或条件格式求值。字段画像使用共享分析槽位，排队取消不启动读取。

## 接口与界面

- `POST /api/analysis/source/capture`：从成功的`filterId/viewId`捕获范围，核对`workbookKey/book/source`；选区另带端点及有效冻结边界。返回运行时`id`和规范化`sourceScope`。
- `POST /api/analysis/source/restore`：按保存规则重建筛选和显隐；不修改当前网格或持久偏好。未知组、来源变化和端点错配拒绝恢复。
- `POST /api/analysis/source/clear`：只释放相应拥有者。
- 字段及画像GET接口可携带`sourceId`；查询启动的`sourceId`不进入保存的Query，服务端从成功快照取得实际范围。
- 下钻和明细可携带完成结果的`jobId`，核对来源/表头/范围后复用其引用。只带保存Query时按规则重建，不忽略`sourceScope`。
- 异常及分析方案捕获从完成任务固定范围；排队异常CSV有独立引用，不依赖结果目录继续存在。

分析工作区提供完整源表、完整筛选结果、当前可见行和画面选区；后三者只能捕获同一工作簿当前网格工作表中已完成的状态。更换其他来源仍可读取完整表，已保存的范围可独立重建。范围捕获及字段准备成功后一起替换当前设置，失败保留旧范围；完成结果单独显示其范围，后续修改Builder不会改写结果来源。

`analysis-sources.js`独立管理当前拥有者及待提交来源。取消、切换及关闭后的迟到捕获仍读取其返回ID，只释放该ID；范围、字段、画像和下钻均校验各自请求意图，工作簿身份包含内容及路径。字段/画像请求可取消；来源捕获/恢复请求保留响应归属，取消选择后若服务端尚未结束，完成时回收返回的拥有者，不承诺此类同步请求瞬时停止计算。

字段预览成功前禁用运行；切换已保存报表时，旧结果保留但其导出/提取操作暂时禁用，成功后绑定目标报表任务，失败恢复旧结果操作。保存报表、仪表盘及缓存保留实际完成Query中的Scope；下钻和提取明细携带完成任务ID。范围恢复失败不会改成整表读取。

分析方案的Origin保留原范围作为来源说明；可重放步骤不把旧工作簿范围隐式套用到另一个目标。方案目标默认完整源表，可明确选择当前分析范围。预览/运行顶层的`sourceId`只绑定目标快照，不改变双表对账的来源协议。预览仍以完整源表头判定名称唯一性，再按选区保留原列ID；类型样本只读所选范围的前8条。表头摘要及范围摘要共同守卫重放，任务在排队前独立持有范围。结果接回Builder前按同一范围读取字段并核对摘要。

## 持久化与兼容

旧工作区版本1继续读取。首次保存含`sourceScope`的报表时写版本2，随后不自动降级；载入、保存和备份校验共享规则。旧应用拒绝版本2，不能忽略新增范围后改做整表分析。未知版本、字段和损坏文件保留原文件并报错，不写入默认范围。源索引和值缓存不迁移。

联合来源报表另使用工作区版本6，定义内逐份保存已确认的范围及身份；单表版本2范围契约不变，不用一个顶层范围覆盖所有输入。已完成的联合任务、层级展开及异常导出通过同一拥有者独立借用多来源快照。

分析方案目录和步骤版本不变，新增可选Origin范围说明。严格的旧读取器拒绝含未知字段的记录；新读取器校验指纹及范围版本，普通旧方案继续兼容。

## 当前证据

定向服务回归核对预览、画像、聚合、下钻、明细的行号和数值；完整筛选、可见冻结及正反选区的不同集合；稀疏空白、超已用空白行列、全隐藏；保存规则恢复、端点错配和未知配置拒绝；排队清除/取消、池淘汰、并发消费者及App关闭后的独立引用；异常CSV排队后清理全部分析拥有者；前导零和公式缺缓存；分析方案来源范围。

百万CSV专项生成100万条记录，隐藏前50万条数据后聚合其余50万条，独立逐条核对全部可见记录的源行、精确金额、编号及类型，源SHA256不变。捕获分配观测17,136字节，未创建50万项行号向量；6,057ms是本主机该合成输入的一次聚合观测，不是前后比较或普遍提速结论。

本工作包完整标准与完整竞态通过，含250项前端回归。类型迁移触发的旧未命名结构体初始化已补齐字段名，保留首次vet失败收据，没有关闭检查。

真实服务HTTP专项通过隔离浏览器会话发起真实服务请求，核对预览/画像/聚合/下钻/明细的源行和类型，原拥有者清除后的读取，版本2报表备份/恢复，以及完整筛选、可见冻结和画面选区的不同精确计数/合计；源哈希不变。这是接口与数据验证，`sourceChoiceUIAcceptance=false`，不代表已启用新来源选择界面。

基础工作包重新构建后的既有分析和方案流程当时通过，仅证明当时的完整来源行为。本轮新增来源选择浏览器专项已通过：真实拖选、原列号、原生文本/公式缺缓存、画像、聚合、完成任务下钻及提取、清除拥有者、不同范围报表/仪表盘、版本2备份/恢复、选区方案重放、排序冻结、取消迟到、420px范围控件及重载后范围恢复。源SHA256不变，Office/WPS和桌面人工验收均未进行。

本轮完整标准检查及完整竞态检查通过，含262项前端回归；重新构建后的既有分析流程和分析方案浏览器通过。旧分析流程首先暴露了报表切换准备期间仍可点击旧结果操作的问题，补齐等待守卫后重跑通过。
