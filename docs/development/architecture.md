# 包职责与依赖

项目保留一个 Go module。`cmd/` 负责启动，`internal/` 按职责分包；源码跟随职责和测试放置，不按版本复制代码。文档归档不会改变用户文件、指纹、索引或分析工作区。

```text
cmd/excellens              启动、单实例、托盘与本机服务装配
internal/formats           格式支持名单、源类型语义、容量和显示能力
internal/valueconv         显式日期/时间解析；只处理调用方给出的短文本
internal/sourceview        声明式来源范围、筛选/排序和显隐设置；不读工作簿
internal/workbook          格式适配、源值/布局、索引、缓存与查询
internal/archives          容器目录、按需提取、完整性及缓存固定
internal/analysis          精确十进制、透视、独立分析工作区
internal/calculator        有类型的公式语义与运算
internal/recovery          有界、校验及持久化确认的页面恢复日志
internal/checkpoint        独立任务的来源/规则绑定、完整块及确认游标；F21基础
internal/editdoc           有类型稀疏变更、编辑修订、持久撤销与重试收据
internal/editfile          编辑源全量预检、按源坐标读值及验证新副本
internal/opc               ZIP 部件的原压缩复制、流式替换和完整性核验
internal/separated        保留格内换行的分隔文本转义及文字保护
internal/reconcile         双来源精确核对、重复组与完整明细
                           显式关联完整预检、保留行序及有界配对提取
internal/recipe            声明式分析步骤、字段绑定与匹配规则
internal/export            公共流式导出与 XLSX 快照
internal/printing          来源绑定的纸张/缩放/重复标题及有界物理分页
internal/clustering        显式Unicode候选键、有界排序及原文分组
internal/composition       只读多来源字段对齐、流式追加及源格追溯
internal/server            HTTP、会话、任务及业务装配
internal/ui                嵌入的 HTML/CSS/JS 与格式配置注入
internal/tray, shellmenu    Windows 用户入口
internal/buildinfo         唯一应用版本
tools/project              统一检查、格式化及生成命令
tools/qa                   专项回归、可选性能和私有样本检查
```

### 服务入口和前端组件

网格正文和冻结窗格通过 `multiselection.js` 判定单元格是否在选区内。`range-frame.js` 按当前缩放、滚动位置、冻结边界和可用视口绘制外框。一个连续区域最多生成四段轮廓，冻结分界线和屏外裁切处只绘制实际可见的选区边。选择端点、框选底色和显示角标都留在视图层，工作簿的单元格格式仍由格式适配器提供。

原生文件打开入口先分配独立会话，该会话的首次 API 调用再读取文件。网页等待任务由当前文档的 `activity.js` 持有。一次任务可以连续跨过传输、解析、索引和显示阶段，轮询、取消和迟到响应均使用原任务句柄。已有进度区可接入同一指示器，空闲文档不订阅其他页的任务。`motion.css` 负责控件与弹层的时序，网格坐标和大小直接更新。

工作表索引与窗口读取在 `server/sheet_http.go`，筛选和搜索各有自己的 HTTP 入口与任务生命周期。分析工作区、源字段、查询任务、结果导出分别在 `analysis_workspace.go`、`analysis_source.go`、`analysis_query_job.go` 和 `analysis_results_http.go`。按区域扩展的分析列和普通分析列共用字段命名，稳定的字段 ID 绑定源列号。

界面的 A1 坐标转换由 `cell-address.js` 提供，调用方传入来源容量。命令检索、键盘选择及可用性判断由 `command-palette.js` 管理，操作回调由应用装配。视口的覆盖范围、字节估计和缓存淘汰由 `viewport-cache.js` 管理。网格请求直接持有写入或复用的条目，缓存总量由同一组件维护。

复制沿用当前工作表的源合并索引，无需读取虚拟网格的 DOM。普通视图将矩形扩到完整的合并范围后计算容量。编辑副本网格按本次修订投影选区内的值和公式结果。HTML 表格在左上角写入 `rowspan` 和 `colspan`，TSV 在覆盖坐标写入空字段。行序发生变化时，只对按源顺序相邻的对应行写入跨行合并。Windows 由浏览器将 HTML 片段写成系统剪贴板格式。原生回归从该剪贴板执行普通粘贴，逐格读取 `Value2` 和 `MergeArea`，并检查矩形外围。[HTML 表格模型](https://html.spec.whatwg.org/multipage/tables.html#table-model) · [Windows HTML Clipboard Format](https://learn.microsoft.com/en-us/windows/win32/dataxchg/html-clipboard-format) · [Excel Range.MergeArea](https://learn.microsoft.com/en-us/office/vba/api/excel.range.mergearea)

### 从一次格内编辑到一个可下载的副本

1. `server/edits.go` 负责 HTTP 路由、请求解码和错误映射。`edit_session.go` 持有底稿绑定、租约和恢复，`edit_cells.go` 将读格、候选选项和提交接入当前修订。`editdoc` 确认一批变更并维护撤销和重做。
2. `workbook` 将标准数据验证和 Office 扩展验证解码为同一个源规则，解析工作表名称和绝对区域。`editfile` 按目标坐标取出规则，使用底稿、当前修订和整批拟议输入核对下拉来源。工作表保护、合并、数组和透视结果各自提供覆盖区域。
3. `editfile/xlsx_parts.go` 登记部件路径、内容类型和关系。`xlsx_styles.go` 读取实际单元格样式索引及锁定状态。`xlsx_tables.go` 沿工作表关系绑定表格范围和字段，`table_edits.go` 将用户输入展开为经过保护和数据规则检查的单一事务。普通表可完整扫描，大型表通过 `xlsx_window.go` 将目标和共享公式锚点映回源部件的字节偏移。
4. 两种扫描路径都将按源偏移计算的修改交给 `xlsx_parts_write.go`。`opc` 按部件流式复制或替换，重读输出核对条目、CRC 和 SHA-256。`editfile` 随后重读坐标核对实际值和类型，`Outputs` 发布通过核对的副本和修订收据。

生产包与 `cmd/excellens`、`cmd/perfprobe` 的导入边界由 `tools/project/architecture.go` 检查。生产代码只能导入登记的仓内包，`opc` 的依赖必须来自 Go 标准库。添加部件时，在 `xlsx_parts.go` 登记识别与关系约束，在对应语义模块处理它对可编辑区域和重算的影响。

#### 修订、底稿与生成件

`editdoc` 在 `edit-documents` 中记录单元格值、样式、矩形规则和计算列模板的前后状态，复用 `checkpoint` 的系统租约、块摘要和确认记录。新建文档采用编辑语义 7，版本 1～6 的已确认记录可重放。旧布局按绑定底稿重新识别可写坐标。操作按修订提交，重试可取回已有结果。底稿从只读句柄按 SHA-256 绑定，独立生成件和收据保存在 `edit-files` 中。打开生成件会走公共工作簿读取入口。

整行列、表名和透视图表操作共用 `server/edit_structure.go` 的文档租约。`editfile` 先合并当前修订，再按 OPC 关系重写有关部件，核验后以修订号保存到 `edit-revisions`。日志记录新底稿的身份、摘要及布局，撤销时切回前一底稿及其稀疏输入。服务重启后从同一份日志恢复。`edit-tools.js` 负责工具选择和表单，网格、生成与恢复沿用同一个编辑控制器。

透视字段布局和分页选择由 `editdoc.PivotAxes` 表示，原始类型随选项保留。`editfile/pivot_schema.go` 匹配当前源标题和缓存字段，`pivot_items.go` 管理字段项的序号、顺序及筛选，`pivot_axis.go` 聚合两轴祖先的交叉点。`pivot_matrix.go` 决定单元格结果，`pivot_layout.go` 将对应的轴定义写入同一副本。浏览器的 `edit-pivot.js` 只在打开筛选时读取绑定到当前修订的候选，网络响应不会覆盖新布局。服务端从同一个修订快照取得源索引、输入覆盖和公式结果。分页游标最多保留该修订最近使用的一列，读取到下一页的首个项目即停。搜索复用已读的带类型项目，修订或字段变化时更换游标。中文排序使用 go.mod 固定的 golang.org/x/text。

`EditBatch` 将底稿、当前修订和本批拟变更合并校验，下拉候选按来源坐标排序，因此同批新增选项与选用该值可以一次提交。`/api/edits/choices` 按需返回当前修订的文本选项。剪贴板版本 1 可接收文字，版本 2 可携带类型及样式。样式、格式与规则的预览签名绑定进程和对应修订。

修订内计算由 `calculator` 解析公式，`editfile` 维护依赖和结果。普通报表按依赖传播缓存失效。公式结构变化时移除旧计算链及其关系与内容类型声明。大型台账的按坐标写出路径保留宿主公式和计算设置，发生编辑时标记 Excel 重算，需要在重算后刷新的透视缓存单独记入生成收据。数据规则和既有验证信息保留在各自的工作表。 [计算过程及边界](xlsx-grid-editing.md)

F21的`server/search_checkpoint.go`将既有普通/公式/引用/高级搜索接入独立`task-checkpoints`目录，来源路径/内容/解析及规则版本与精确索引/行缓存签名分开绑定。全簿按源表顺序确认阶段，每4096条完整记录保存小游标，仅新增命中进入完整块；`workbook/search_resume.go`在保留命中前计入独立恢复容量，普通搜索不套用该容量。`task_checkpoint.go`只列有界元数据，恢复要求预期修订与相同来源；丢弃在OS租约和目录锁内原子核对修订。任务沿用共享查询/索引槽和源固定/取消/关闭生命周期，目录准入仅对未改变持久状态的锁忙做可取消短重试，不重试不确定写入。可靠文件修订直接绑定缓存，不具备可靠修订时流式SHA256回退；来源及缓存变化拒绝恢复，不隐式重扫。查询、六格式公共导出及紧凑恢复界面均已接通；实际验证边界见[恢复记录](task-recovery.md)。

F21筛选/排序由`workbook/filter_scan.go`共享原编译条件、列缓存和比较器，`filter_resume.go`发出完整记录源位置并从完整筛选行序重建排序；恢复后半段不能发布缺前缀列缓存。`server/filter_checkpoint.go`/`filter_checkpoint_order.go`将32位位置流接入相同持久目录，先完成私有、唯一/范围/表头及成员验证，再经公共`RowOrder`发布；排序重建必须核对已确认的输出前缀。`checkpoint.VisitCandidate`边读边验完整摘要/链，只允许私有候选，不改变原`Visit`的先验契约。来源/租约和短重试由`task_checkpoint_source.go`及`checkpoint_retry.go`复用，搜索封套不变；筛选状态先取独立快照再写HTTP，避免慢客户端占任务锁。界面恢复沿用原网格/可见行提交；已确认的完整条件数组供高级筛选后多级/表头排序共用，保留同列多条件，不以单条件表头Map替代原查询。

F21导出输入由`server/export_selection.go`共用原范围装配，`export_checkpoint.go`持有来源/精确索引、输出选项、隐式物理范围及显式源行摘要；不持久化filter/view/job ID。`workbook.SourceRowSnapshot`用内部坐标序列复用有界行序存储、唯一性/映射/配额和引用，不暴露成物理记录的`RowOrder`；源行引用计算复用普通读取的迭代器。`export_checkpoint_rows.go`以同步迭代器在单次`VisitCandidate`中跨块重建私有快照，全部摘要/形状/来源验证后交还输入拥有者。`capture`中断明确要求重选，`ready`只确认输入，不能当作输出完成。普通导出仍不创建持久任务；显式recoverable路径已接六格式驱动与公开任务/恢复/下载，整项验证边界见恢复记录。

`tools/project` 用 Go AST 检查全部平台生产源码的导入，不受当前 GOOS 构建标签影响。测试可装配多层。新增包或跨层依赖必须同时说明职责并更新规则；禁止用空接口或通用 util 包绕过职责边界。

F18的`reconcile/relation.go`复用原有源类型/显式文本或精确数值键和`workbook.SortKeyStream`；公共`BuildRowOrder`向已有有界行序构建器流式提交位置，共用逆序、校验、映射引用和临时磁盘配额，源缓存编码不变。预检只归并键组起点及计数，输出数量用int64并以字符串编码。`relation_order.go`在每组内按原序保留七模式各前100个紧凑候选，不能进入全局前100条时跳过剩余组合；预览直接读取固定位置，不再次归并整表。完整提取先核对上限，再经共享有界排序恢复左表原序及同左记录的右表原序；仅右侧模式按右表原序。配对元数据固定45字节，不复制源值，双读取器复用连续相同位置，不缓存整组；状态/来源/匹配数量不一致的记录拒绝。完整CSV按字段列输出原值，附对齐的类型/存在/缺缓存/源列数组；来源固定、检查及原子发布归server。`server/relation_source.go`复用`buildTypedTableSource`，单独的64列容量不放宽旧对账限额；原生文件及分析表内容版本在每次操作前后核对。来源/内核/CSV与任务和界面的实施边界见[关联记录](table-relations.md)。

F18的`server/source_lease.go`统一输入、完成来源及编码响应的独立引用，最后释放清空载荷，不能用关闭句柄继续保留未计费正文。`relation_snapshot.go`排队前固定双来源，准备另借输入；`Source.RetainedBytes`记录分析表选定投影费用，公共`RowOrder.RetainedHeapBytes`与`Relation.RetainedOrderHeapBytes`区分驻留数组和磁盘映射页，快照Go堆计费跨标签共享，不宣称是总RSS上限。`relation_tasks.go`按完成预检派生七模式任务，状态轮询不重复传正文；候选完整成功后发布，旧结果保留，清除/切档/关停只摘取自己拥有的引用并锁外回收。结果GET另借编码字节，写网络前归还查询槽和缓存锁。字段读取共用F17异步字段任务及源签名，`relation_export.go`复用公共导出中心和原子发布；`relation_navigation.go`验证两侧真实原格后接公共导航。当前后端与界面的验证边界分开记录，不增加源写回、缓存编码或运行依赖。

F17/F18的字段选择统一由`field-picker.js/css`负责单选、多选、搜索、有限分页和迟到按钮隔离；原始表头对应使用一次摘要索引，只建议完整唯一的表头。`composition-tasks.js`的`ExcelLensSourceTasks`复用来源身份、轻量轮询和独立令牌回收，可接入不同业务端点。`relations-model.js`在DOM外核对精确整数、完整查询/来源、七模式形状、原值状态、原序及响应容量，`relations.js`只在完整候选和视图均成功后替换旧结果。列数按实际容器宽度分页，尺寸和主题变化只重绘现有结果；全量CSV仍经公共导出中心，切档与迟到导航各自清理拥有的资源。

`server/persistence.go`按持久化文件路径提供读写锁，标记及分析工作区的读改写跨浏览器会话串行化；先取得App自身的锁，再取得文件锁。选区的源行映射由`server/selection_rows.go`拥有，复制、即时统计及选区导出共同调用；前端保留端点与可视行号配对。TSV编解码和粘贴边界验证统一在`ui/web/clipboard.js`，解析及验证全部成功后才创建编辑请求。

F10的`clipboard-special.js`将公共读取的CellData转为TSV/Markdown/版本1 JSON，并生成独立编辑表的文字变更计划。`clipboard-panels.js`负责读取、取消、迟到请求处理、有限预览和显式保存。复制行列、格数和字节预算由`formats`统一注入。`/api/range`可在同一来源的有界读取中附带一个源表头行，表头计入容量。开始及发布前核对工作簿、工作表、选区、筛选及可见视图。独立编辑表粘贴沿用草稿、修订号与一次`ApplyEdits`。编辑副本的有类型值、公式和普通样式走单独的修订绑定接口。

`server/saved_config.go`拥有供命名视图、分析方案、行显隐及分析显示偏好使用的用户配置封套，提供有界读取、严格结构、版本/校验和、Sync及保留旧文件的替换。命名视图从成功的`FilterResult.Spec`捕获规则，按源内容和字段签名验证后重新使用公共筛选链路；查询失败不覆盖当前网格，不持久化整表或临时行序。配置路径不参与缓存维护，跨页面保存需预期修订号；详见[实现与验证](named-views.md)。`server/analysis_display.go`单独维护跨工作簿的显示偏好；`ui/web/analysis-numbers.js`仅格式化聚合单元格，以十进制文本/BigInt处理千分位及科学计数法，保留原始Cell与精确提示，不参与源值解释、查询身份或导出。

`sort_order.go`和`sort_run.go`完成比较键分段排序。驻留数组、字符串分配余量及双缓冲归并头计入64MiB工作预算，短文本复制自身字节，避免保留大源字符串。小结果内存快路径与`ELSORT01`排序段共用精确比较器、五级键和源位置并列规则；自然顺序是显式文本模式。归并按比较键实际最大长度进一步收紧最多16路扇入，头/长度/CRC/源位置/段内顺序校验全部通过后才发布结果。排序阶段保留单独进度，取消或失败不会替换旧视图；详见[实现与验证](row-order-and-sort.md)。

`server/filter_result.go`在结果表锁内取得独立行序引用。请求和导出结束时释放自己的引用；淘汰、清除及切档释放结果表引用，最后一个引用才解除映射、删除私有文件并退还空间。finalizer仅兜底，不依赖GC及时性控制磁盘预算。完整筛选导出直接持有该顺序，视口只复制有限页；明确包含空白冻结行的选区目前仍使用已有有界源行号数组。

临时查询文件统一由`workbook/query_file.go`登记：共享8GiB和8192文件预算只由formats定义；登记/创建与中断文件清理使用同一锁，避免Unix上活跃文件被误删。文件名携带进程归属，其他活跃进程已经关闭句柄的排序段也受保护；无法确定进程状态时保留文件，PID复用时可能保守延迟回收。删除失败仍计费并重试，当前及历史缓存清理保护在用查询文件。`selectionRowView`共同处理冻结位置、可视页和源格定位，手工源范围通过成员秩取子集，避免扫描全部显示顺序；计算选区按实际可视位置访问。

`indexedStream`共享正向/反向预读：相邻递减源偏移向后取1MiB窗口，分散跳转采用16KiB对齐小窗，防止倒序导出为每条短记录重复读取1MiB。窗口仍按已校验的源偏移切片，XML严格回退和外部二进制解码语义不变。

`workbook.SortKeyStream`为对账投影复用排序段及预算；`reconcile`用源类型和长度编码复合主键，两侧迭代归并且不展开重复键的多对多组合。`server/source_pins.go`与共享缓存锁保护跨标签来源、附件、上传和排队导出，结果清除不提前回收其他使用者。样例有界、完整CSV沿同一快照重跑并核对全量计数。实时定位另核对来源身份，失效时拒绝跳转；详见[对账实现与验证](reconciliation.md)。

纵向导航复用工作簿单句柄流式扫描，以连续占用区间缓存并二分查找边界，缓存按切片容量计入64MiB总预算，最多16列；扫描复用共享查询限流，取消与切档不发布过期结果。列缓存从字典转为完整字符串数组前，先核算展开后的预算；无法缓存时继续原始扫描。

`recovery`包不解释公式或业务类型。`server/recovery.go`按用途验证输入，根App的所有标签共享同一个Store和独立恢复限流。`ELREC001`帧包含长度、CRC、修订号及请求摘要；重试必须匹配数据和版本。文件名以小写Base32可逆编码页面标识，避免Windows大小写文件系统合并不同标识。未完成尾帧先保留证据，完整帧损坏失败关闭；检查点交换保留备份。单副本8MiB/20,000项、单项64KiB、日志64MiB、最多64个且32MiB计费的内存缓存。该计费不是整个Go进程内存上限。恢复数据不参与缓存清理。

`analysis/aggregate.go`按字段合并指标需求，一条参与记录的同一指标字段在聚合与诊断时共用一次精确解析；各合计分别更新，仅维护需要的状态。`analysis/issues.go`共享转换失败、数值排除和缺缓存范围，聚合只保留前100个、最多512码点的样例；提取和完整流式CSV使用同一诊断访问者。编辑表内容按行流式摘要绑定分析任务，防止相同数字修订号掩盖不同内容；元数据读取不额外计算整表摘要。

F09的`analysis/comparison.go`在原始第一指标精确排序之后、Top-N之前为每个指标生成独立`Cell.comparison`，原`exact/display/count`不变。完整行/列/范围分母来自同一扫描；双向累计合并原累加器状态，平均保留权重、去重合并文字集合，不相加非加性子结果。额外集合/输出计入同一查询工作预算，按需层级只处理当前父范围；取消/超限不发布部分派生页。保存比较查询的工作区使用v4、分析方案使用步骤v3，旧版拒绝而非静默丢弃。公共结果表保留精确比值及状态，XLSX同时检查15位精度和Excel数值范围，不能落成下溢0。前端比较模型统一标签、范围及原始/派生提示，原数字设置只增加派生值和百分比单位适配；图表采用近似绘图并保留精确提示。详细证据见[占比与累计](analysis-comparisons.md)。

F11的`clustering`包只在显式任务中规范化可信文本并复用`SortKeyStream`分组：分段十六进制键保留规范文字/源类型/原文/源行/公式状态，不以哈希相等代替原文。单次来源扫描、确定排序、完整次数和有限位置样例受独立候选预算保护，失败不发布部分结果。`server/clustering.go`复用泛型元数据任务/查询槽、来源范围独立引用、路径及精确索引；确认限定组内原文，只产生声明式`map_text`列，候选CSV复用公共导出槽和原子发布。`analysis.Value.Textual`仅表示公共读取确认的文字匹配资格，不能改变数值解释或冒充完整源类型；映射按有序表二分且不级联。工作区5/方案4保存新语义，旧版拒绝，源值/索引/布局缓存编码不变。`formats`统一能力及容量，SQLite缺少可靠存储类型时拒绝，不按占位文字猜测。界面失败保留成功结果，取消/迟到/分页/确认/导航分别守卫。实现和验收边界见[疑似重复值聚类](value-clustering.md)。

异常CSV和普通源导出复用`newExportJob`及`publishExportFile`，统一任务数、共享导出槽位、取消、下载票据、临时文件同步与发布。浏览器只接收进度和下载链接，不物化完整异常列表。编辑副本提取另受10,000项、单格4000码点和16MiB文本预算约束，截取明确标注。

`analysis-jobs.js`拥有开始请求、取消、轮询及完成任务，开始响应在取消后返回时继续回收该自有任务；序号和工作簿身份决定是否可发布进度与结果。`analysis-results.js`以工作簿和查询为键保存完整结果快照（结果、查询、任务编号），LRU最多8项，保守估算引用结构和UTF-16文本不超过24MiB；大结果仍可作为当前结果显示，但不加入缓存。缓存预算不代表活动图表、当前结果及整个浏览器的总内存上限。

单格编辑容量由`analysis.ValidCellText`以合法UTF-8及Unicode码点校验，编辑、持久化及备份验证共用；`clipboard.js`保持相同字符语义，并分别验证原始UTF-8文本及JSON编码后的2MiB请求预算。一次粘贴为原子事务，只有用户明确重试的既有独立草稿允许按字节及格数预算分批。原工作区版本1继续读取；首次保存带来源范围的报表时使用版本2，旧应用明确拒绝，防止忽略范围后扩大为整表。载入、保存及备份校验共用版本/范围规则；索引及源值解释不变。

查找范围仅在访问者明确声明`RangeValue.Ordered`时允许正向精确或通配查找提前结束；数组与单列流式范围声明此能力，反向、近似及未声明有序的范围保留完整语义。图表只将精确结果转换为浮点绘图值，分数用有效数字和数量级近似，缺失值、超出浮点范围与真实零分别处理，不改写计算结果。

`sourceview`拥有可保存的筛选/排序、显隐设置和带源/可视端点的范围规则；`workbook`以类型别名沿用既有接口及规范化实现，布局v6和各值缓存编码不变。`server/analysis_source_*`捕获或重建同一来源范围，以独立引用持有源、索引、完整筛选、显隐及流式选区计划。任务、画像、下钻、明细、异常和分析方案读取共用该快照；临时ID不进入保存的查询规则。字段画像复用分析槽位，取消排队不读取数据。界面接入和验证边界见[工作区来源实现记录](analysis-sources.md)。

`sourceview.Append/TableRef`描述有序的只读联合来源及显式列映射；`composition`按列流式追加并分开保存追加序号和真实源格。`server/composition_source.go`绑定公共适配器和独立来源引用，`composition_tasks.go`拥有异步准备、取消/清除/淘汰及切档/退出；释放映射、来源和预算在App锁外执行。工作线程先取得共享查询槽再取得缓存读锁，范围恢复借用已有槽；其他调用仍走原来的限流入口。`composition_budget.go`在根App对排队配置、保留响应和来源快照统一计费，最后借用者关闭后才退还源预算；新格式及源值/索引/布局缓存版本均未改变。当前任务包已验证，分析/持久化及界面接入边界见[多表追加记录](table-composition.md)。

`analysis/tree.go`只查询当前分组层，复用同一十进制、转换和筛选执行路径；`server/analysis_tree.go`以已完成根任务绑定来源，排队前固定独立引用。子任务另设有界历史及结果字节预算，不淘汰根报表；关闭等待任务退出，取消不发布部分结果。`analysis-tree.js`拥有独立分支意图、取消/迟到响应清理、前缀树及有界LRU缓存，渲染按根列键对齐、分页且不创建未展开后代。层级报表使用工作区版本3，层级分析方案使用步骤版本2，旧版本明确拒绝。实际输出范围及验证边界见[层级透视记录](analysis-tree.md)。

## 格式链路

关联导出O01的`reconcile/relation_csv_metadata.go`只缓存有界、完整相等的类型/状态JSON，不保留源值，签名碰撞和容量拒绝均走真实编码。`relation_csv.go`复用自己的记录槽并在每次返回前清空借用文字；来源身份、原列和CSV语义不变。`export/csv_archive.go`为服务器的普通CSV生产器提供单成员标准ZIP流式封装，64KiB间隔检查取消，关闭/写出错误向原子发布层传播；不写未压缩中间文件，也不改既有多表ZIP/断点续写压缩器。格式选项和推荐阈值统一由formats注入，公共导出中心显示实际ZIP格式，旧无format请求仍输出CSV。边界与测量见[优化记录](relation-export-optimization.md)。

任务生命周期O02沿用现有任务与来源模型：状态接口在锁内取得状态和已发布的不可变结果引用，锁外JSON编码/写网络；不为缩短锁而复制整份分析表。导出准入和历史淘汰以`done`确认工作协程及其资源回收，按时间淘汰最旧的已退出任务。对账`closeSources`统一锁内摘取、锁外回收双来源，失败/取消不让历史继续固定来源，成功结果和已排队导出各保留自己的引用。专项与验证边界见[生命周期优化](task-lifecycle-optimization.md)。

O03的`server/query_history.go`在App锁内共享筛选/搜索的退出边界与最旧回收，容量统一由`formats.QueryTaskHistory`维护，普通、磁盘缓存及恢复准入均不得绕过；仍有在途拥有者时限流。被拒绝的新建恢复点只丢弃自身未发布的精确修订，已有恢复被拒绝时保留确认点；释放/丢弃失败不冒充成功。独立行序和结果消费者不随历史回收而改变，源缓存编码不变。验证器仅在测试中使用真实HTTP与进程采样，见[资源基线](stability-baseline.md)。

F24的`analysis/snapshot.go`从完成结果投影一个显式指标，保留原查询/字段/来源及精确状态，以结构化分类键和系列做有界有理数比较，不读取原表。`server/comparison_snapshots.go`只接受完成任务ID与来源身份，从服务端捕获；独立版本1目录复用公共配置封套、路径锁和预期修订，不改变分析工作区或源缓存版本。目录/详情及比较均在网络写入前释放持久锁，比较共享分析槽并在编码完成后归还；取消在逐分类边界检查。`snapshot-model.js`拒绝身份/形状/容量错位，`snapshots.js/css`拥有两侧接受结果与迟到守卫，小趋势复用公共图表数字语义和共同刻度，容器/主题变化只重绘。具体边界与验证见[比较快照](comparison-snapshots.md)。

所有入口从 `formats` 获得扩展名；压缩包解析与文件格式解析各自保留具体解码分支，避免支持名单和真实实现混为一谈。浏览器配置随首页一次注入，不再维护另一份扩展名、源格式容量或样式名单。

适配器输出统一的 `Workbook` / `SheetMeta` / `CellData` / `SourceLayout`。XLSX/XLSM 流式读取 ZIP/XML；BIFF8、HTML、文本和 SQLite 转入已有二进制行缓存。两种缓存共用行读取、查询、视口和导出接口，不为新增显示问题重新实现网格。

源布局v6侧文件另外保留压缩显隐/大纲区间、默认隐藏/零尺寸、显式正尺寸及条件块XML范围/命名空间；旧v2～v5不复用，OOXML从缓存XML标签流迁移，BIFF8重读布局记录，不重建源值索引。布局加载同表合并，IO不持map锁，等待者可取消。`conditional_*`提供DXF差异、二维范围索引和有界精确求值；未知结果不当false。`RowReadOptions.ConditionalFormats`显式接入公共批量/流式读取，派生显示与样式单独存放，源字段不改写；`reader_numbers.go`覆盖真实缺失行，不修改值索引。引用复用同一句柄并计费，普通值读取不启用。主/冻结网格、复制与HTML共用呈现模型；XLSX以源XML保留补丁和有界样式去重冻结当前效果，流式工作表后写出样式表。条件快照边界见[实现记录](conditional-formats.md)。

`axis_visibility.go`使用不可变压缩区间、事件扫描及rank/select生成显隐映射，源状态、默认零尺寸、组层级及本机覆盖分离。`row_projection.go`只对既有`RowOrder`的位置加掩码，不复制行序或重建逆向索引；4096位置分块，全显/全隐合并，混合块用位图。超驻留预算后使用`ELRPR001`校验映射，共用查询磁盘/文件数预算；每个调用者持独立引用，最后引用回收掩码及其原行序引用。`At/Iter`返回源索引位置，并非Excel行号。投影构建的行数/容量检查不能证明源身份，业务层另行绑定真实来源。

`server/row_view*`负责可见行任务、来源绑定、不可变快照及持久显隐设置。异步构建共用查询槽位，按Workbook对象/内容及路径身份、精确索引对象、Sheet、筛选和显隐摘要绑定；同表旧任务取消，迟到结果不能发布。配置位于用户配置目录`row-views`，复用`saved_config.go`封套与按路径锁，提交前核对预期修订号；Sync/替换失败保留旧设置和旧视图。服务最多4份拥有者快照、2个活动任务，调用者独立引用可跨清除、淘汰及退出继续读取；最后引用释放源固定、完整筛选及投影。源状态不写入用户偏好，临时显示不持久化。损坏偏好仍拒绝默认加载/持久保存；用户提供明确的非持久设置才可恢复显示，快照携带警告并保留原文件。`selection_snapshot.go`统一取得完整筛选与可见投影的组合引用；`selection_rows.go`在冻结前缀中跳过隐藏行，视口、复制、统计、计算取数及选区画像/检查通过可选`viewId`接入。手动源范围保持原语义，详见[实现与证据](source-fidelity.md)。

`selection_row_plan.go`用一个源区间和一个可视区间描述选区，与有界复制/统计共用端点及冻结规则。`AxisVisibility`、`RowOrder`和`RowProjection.IterRange`直接定位所需片段，混合位图逐字流式访问，避免为大选区展开行号或扫描整个前缀。`SourceRowReference`携带源行号及已知索引位置，共享单句柄读取器拒绝错位索引及伪造空白；原值/缓存编码不变。`export.RowSequence`是借用的只读行流，验证索引对象、声明数量及实际完整性。`server/export_rows.go`在排队前保留来源及选区组合引用，完整筛选与可见范围分开；物理连续区间沿原坐标映射保留合并，非连续/重排采用紧凑快照。命名视图v2仅保存成功快照的显隐设置，恢复时重建查询和投影，前端能力守卫拒绝部分应用；当前网格已启用v2。`row-views.js`拥有客户端任务及有界快照缓存，迟到响应按自己的任务ID清理；提交另核对来源/Sheet/筛选意图和视图身份。`row-visibility.js`与`geometry.js`使用压缩区间支持源行秩/选择及像素反查，主/冻结网格、方向键、选区和对应导出选项均已接入。分析工作区已通过同一快照接入来源选择，见[分析来源](analysis-sources.md)及[流式与界面记录](source-fidelity.md)。

普通及条件数值的常见定点显示共用源十进制舍入，General原值快路径保持，日期按源序列语义处理；不将原生Excel文本自动转数值。普通XF的显式apply=false委托named cell style，缺省仍使用单元格XF。搜索结果缓存v3拒绝旧显示产生的v1/v2命中，值索引、外部行编码和用户工作区不变。

数值、文本、布尔、错误及缺少公式缓存必须分开。源格式能力明确决定文本金额是否可用于隐式统计；原生 Excel 按源类型处理。显式公式转换和排序转换继续由对应功能负责。

格式转换复用已存在的分析计算列链路，只在用户运行带转换规则的查询时执行；不写回源、源缓存或字段类型。公式建议只解析当前计算返回的最多256字符文本，不新增源读取，不参与打开文件、索引或视口滚动。按钮把转换写进本行公式，不能隐藏地改变后续引用语义。

筛选视口的请求、缓存及在途覆盖都绑定筛选、可见行视图和实际冻结前缀。地址定位和键盘移动共用滚动几何，提交前核对工作簿、工作表、视图及操作意图。前缀改变后，新视口按源行重绑活动格，并清除仍基于旧行序的范围；离屏活动格由既有定位接口按需解析。

`server/query_admission.go`统一可取消的跨页面查询准入。需要提前捕获的请求在短读锁下保留来源，释放读锁后等待查询槽，读取前再核对快照。分析范围重建由入口先拿槽，联合来源直接借用该槽，冷列导航占槽扫描，已有列定位缓存继续直接命中。

## 大数据索引与扫描

`SheetIndex` 通过 `RowIndex` 提供行数、按位置读取及顺序迭代。搜索取样使用 `FirstRows`，与完整索引共享原坐标、共享公式及映射的生命周期。索引最多在堆上保留 262,144 条偏移。超过阈值时，外部格式构建器先将偏移写入临时文件。原生和外部格式均在索引落盘后映射校验格式相同的只读记录，首次构建与缓存重开适用同一阈值。Windows 在映射使用期间拒绝在线清理。

当前源行索引写出`XLIDX009`，固定20字节偏移记录不变。原生OOXML的旧`XLIDX007/008`因正文范围规则修正而重建，优先重用CRC核验通过的原始XML；外部适配器旧索引仍可读，`ELNROW02`原值/类型编码不变。修正使内联文字的字体、注音及扩展子树不再伪装成值或延长已用区域；查询列缓存仅驻留内存，随Workbook重新创建，无需磁盘迁移。损坏、文件长度不符或越界时重建，重开大索引先核验真实文件长度再决定驻留或映射，避免伪造数量导致大额堆分配。

富文本使用独立`ELRICH01`样式侧文件，不把字体片段嵌入源值缓存。共享字符串首次解析捕获、后续只读映射复用；原文摘要、版本、范围及CRC校验独立进行。`RowReadOptions.RichText`显式请求呈现，分析/筛选/计算维持原读取；单次驻留读取的样式编码预算4MiB，流式访问按行重置，超限保留原文和真实呈现状态。此预算不代表整个Go/浏览器内存上限。详见[当前接入和未完成边界](source-fidelity.md)。

`richtext.js`共用网格与HTML复制的片段边界及安全字体；主网格和全部冻结窗格各有formats注入的8,192片段预算。视口/冻结缓存计入字体模型字节，跨Sheet保留另计片段DOM及旧模型；文本溢出搬移节点。范围复制逐行验证4MiB文字/公式及样式预算后才发布，浏览器另限制16MiB HTML，超限整次拒绝。HTML/XLSX沿公共流式访问者显式读取样式，XLSX不完整样式使任务失败且不发布下载。普通平铺内联值读取使用受限结构快路径，特殊XML回退同一参考解析器。

扫描、筛选、分析和导出复用统一流式读取，保持单个文件句柄和有界预读。超大数据模式阈值、筛选结果数量及容量由`formats`统一维护，前端仅使用注入配置，后端独立校验。

Windows源指纹进程内复用同时核验文件ID、时间、大小及只读`FSCTL_READ_FILE_USN_DATA`修订号，读取期间排除已有写入者；时间戳本身可能在快速改写时碰撞。无可靠修订号、查询失败或未知记录版本时完整哈希，不创建、启用或调整变更日志。此修订号只用于进程内复用，内容指纹域、持久化缓存与源文件解释不变。
