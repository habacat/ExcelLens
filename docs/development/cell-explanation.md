# F20 单格计算解释

接续入口及唯一下一动作见[实施待办](improvement-progress.md#下一工作包)。本包源码及自动化已完成，完整标准/竞态、真实适配器/规模及浏览器通过，5张截图已复核；未提交、发布或进行桌面/Office/WPS人工验收。

## 已核对的行为缺口

`app.js/showCellDetail`修改前直接展示缓存字段：没有公式的单元格也被描述为“有保存结果”，`hasFormula=true`而原文不可还原时可能显示“无”；源类型仍使用n/s等编码。用户无法在现有详情中确认金额是否具备参与数值统计的资格，以及当前成功应用了哪些筛选条件。

本包复用已有“单元格信息”入口，用户点击后才读取单格解释，不在打开、索引、滚动或主界面上增加检测和说明段落。界面只列当前格的事实：源值/类型、数值统计资格、必要原因、真实公式结果状态和实际筛选条件；没有适用条件的项目省略，不堆零计数及工程标识。

## 工程边界

- 资格判定调用`server/source_numeric.go`的`sourceCellNumber`，精确值调用`analysis.ExactDecimalString`；不重新实现文本金额/前导零规则，不把原生Excel文本自动变为数字。已有筛选转换和显式公式语义不变。
- 单格解释固定内容及路径身份、Sheet、精确索引和当前行视图/筛选快照，复用查询槽及源租约；读取前后验证，取消、切档、选择变化和迟到响应不能替换当前详情。
- 复用公共按源行/列读取，先检查源行字节及坐标，独立请求/响应容量由formats维护；明确空白、错误、无效数值、公式缺少结果和原文不可还原。缓存编码和源文件不改。
- 筛选只展示成功`FilterResult.Spec`的事实，不读取尚未应用的对话框控件，不把“具备数值资格”说成“已计入任意分析方案”；当前源格解释不自动执行分析转换或日期规则。
