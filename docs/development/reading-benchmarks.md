# 发行性能基准

1.16.0 起，正式构建以同一组确定性合成文件运行下表。每个读取规模使用新的服务、缓存及浏览器配置。计时包括本机页面和真实读取接口，操作系统文件缓存沿用机器当时状态。首个可见数据格和整屏覆盖分别记录。每组运行一次，跨版比较需同时核对主机、系统、工具链、浏览器、测试代码及样本摘要。

| 场景 | 规模 | 记录或核对 |
| --- | --- | --- |
| CSV／XLSX | CSV 100 万、500 万、1,000 万行；XLSX 10 万、50 万、100 万行 | 选择文件至首个数据格、首屏覆盖、索引请求至完成响应、服务峰值工作集 |
| 滚动 | 百万行 CSV 连续 60 秒 | 浏览器动画帧率、P95 间隔、网格节点与占位层均缺失的帧数、DOM 覆盖状态 |
| 全量搜索 | 500 万行 CSV 中一个机构 | 服务完成时间、CSV 流读取核验用时、每条命中的源坐标 |
| 双表对账 | 两份各 100 万条的合成台账 | 完成时间、数据目录新增逻辑字节的采样峰值、逐类记录数 |
| 多页 | 10、30、64 个独立标签页，每页打开同一份 501 行工作簿 | 并发状态请求的 P95、服务及浏览器工作集和句柄数 |
| 关闭与回收 | 100 轮实际打开、关页并通过任务中心释放 | 每 10 轮采样服务工作集和句柄 |
| 编辑并保存 | 10 万行双表 XLSX | 保存及应用内核验用时、目标值/样式、其他单元格、合并、冻结、跨表公式及部件 |

多进程浏览器的工作集之和包含共享页的重复计数。历史基准仅在测量条件一致时计算差值。24 小时长跑不在发行流程中。

## 1.19.0 综合基线

1.19.1 在这套矩阵中增加六组生产读取入口测量。条件视口每次读取 80 行、48 列，分别按每列有值和每七列有值生成，逐行检查 B 列样式。源行定位在同一份 8,192 行工作表上测试单点、连续正向／反向各 80 行和八个分散坐标，逐一核对行号、列号及原值。每组三轮记录耗时、分配字节和分配次数。另用同一份测试代码对 1.19.0 和本版进行四轮交替测量。[跨版对照](../../validation/1.19.1/viewport-performance.json)

超长工作表会压缩浏览器的物理滚动范围。测量使用网格公开的缩放比例换算逻辑位移，再用源坐标和样本原值验证命中位置。每条条件轨迹记录实际逻辑纵向位移及当时的比例；后端每一轮独立保留结果，即使后续浏览器场景失败也可定位。

正式构建使用第二版报告格式。上表的七类通用场景继续运行，另外测量以下条件格式工作负载。操作系统文件缓存保持当时状态，“冷建”指隔离的应用缓存。普通滚动、条件格式滚动及逐格 Go 微基准各自有独立口径。

## 滚动渲染专项

主区最多并发三次读取，预测读取最多占两路。每次预测按滚动方向、逻辑像素速度、可视宽高和近期读取与提交耗时计算，最多排入 12,000 个单元格，并按近期每格字节估算进一步缩小范围。主区结构化缓存最多 32 块、估算 24 MiB，冻结区另有 6 MiB。超过缓存预算的单块可供当前视口使用。挂载窗口按实际可见行列和文字溢出计算，离屏复用池最多保留 384 个格。样式位图按工作表坐标分块复用，最多 48 块，共用 4,194,304 个物理像素。普通数字格可以复用已验证的样式及边框，源值和可点击坐标逐格绑定。服务及浏览器的实际工作集另外测量。

从待比较的两份源码分别构建 `./tools/uiprobe`，在同一台机器用同一份 `render_perf_qa.cjs` 依次运行。两个输出放在同一目录，脚本会核对工作簿摘要。每版默认三轮，每轮在 1120 × 780 CSS 像素、100% 和 125% 工作表缩放下，分别启动隔离 Chrome 采集计时和截图。测试文件含 1,600 行、96 列、七种底色、四种边框、合并、公式及富文本。轨迹按经过时间推进，包含连续纵移、高速纵移、高速横移、反向移动和一次远距跳转。

```powershell
$env:QA_UIPROBE=(Resolve-Path artifacts/qa/before.exe).Path
node tools/qa/render_perf_qa.cjs artifacts/qa/scroll/before.json
$env:QA_UIPROBE=(Resolve-Path artifacts/qa/after.exe).Path
node tools/qa/render_perf_qa.cjs artifacts/qa/scroll/after.json
node tools/qa/compare_scroll.cjs artifacts/qa/scroll/before.json artifacts/qa/scroll/after.json artifacts/qa/scroll/comparison.json
```

- 合成帧以数据区外的像素标记绑定实际滚动坐标。每条轨迹从收到的合成帧中选取首、中段和末段最多四个位置，回到相同坐标等内容稳定后逐像素比较。分母是稳定图中能确认为源填充或边框颜色的像素，排除文字和抗锯齿过渡色。记录同色面积、异常纯白面积及单帧最大白块总面积。中性占位单独反映在缺失的真实样式覆盖中。
- 计时轮在最多九个分布点核对实际鼠标命中元素的坐标和源显示值。独立的 `tools/qa/scroll_state_qa.cjs` 通过 Chromium 输入接口在正向和反向滚动中点击格子，检查实际点击坐标、选区地址和公式栏。此专项还在读取挂起时检查状态栏和两种主题下的网格底色。停止输入后计至内容核对成功且主网格覆盖当前位置。记录每条连续轨迹的 FPS、P95、P99 帧间隔。单次跳转报告呈现延迟。汇总表中的 P95、P99 是各轮、各缩放各自分位数的中位数。
- 缓存命中率为需要更新挂载窗口时，已经返回的结构化数据能直接满足前台查找的比例。取消率取 DevTools 实际报告的已取消工作表请求数除以发出的工作表请求数。逐帧采集 JS 堆、已挂载格数及缓存估算，另读取独立服务和 Chrome 渲染进程的生存期工作集峰值。
- 常规发行的 60 秒 CSV 测量保留其历史口径。其中 `emptyFrames` 统计页面同时缺少网格节点和占位层的次数。样式覆盖与白块面积使用上面的截图专项。

### 热点与取舍

- 原始 CSV 工作流采样中，搜索占累计 CPU 的 29.4%，两次筛选占 25.0%。热筛选仍花费 34.7% 做数字解析。现在按源类型选择数字比较。对适合的不可变列字典只判定一次每个取值，再沿连续编码每 64 行构造掩码。排序、数值语义或高基数使该路径不适用时，复用逐格筛选。查询掩码表每个字典值占 1 字节，最多 32 个已有字典、每个 4096 项。列缓存继续执行每列 64 MiB、合计 96 MiB 的上限。[各阶段 pprof 与摘要](../../validation/1.20.2/cpu-engine/profiles.json)
- 外部行缓存搜索在结构检查时匹配普通文本。有类型的格仍核对原值和显示值。编号、标点及基本汉字的字面查询复用 Go 标准库子串搜索，由工具链按架构和 CPU 特性选择实现。大小写有关的查询仍按原规则匹配。单独开关字面搜索后，编号和汉字查询的配对耗时分别下降 63.8% 和 68.4%，均为 8/8。位图采用连续小端字读取，`math/bits` 在本机 v1 构建按运行时 POPCNT 能力分派。[字面查询独立对照](../../validation/1.20.2/cpu-engine/literal.json)
- XML 标签名直接与字符串常量比较。管道 TXT 在 `encoding/csv` 借出的记录上做已有的去空格处理，配对长轮每次分配 4.20 → 2.89 MB。精确数值路径在系数和小数尺度可表示时直接构造 `big.Rat`，其余继续按任意精度解析。透视先计算各分组交叉格，再合并精确总和、计数和极值。平均数保持权重。去重集合在扫描每条来源记录时计入原预算，超限当行立即终止。[精确计算对照](../../validation/1.20.2/cpu-engine/final-calculations.json)
- Go 1.27 的 `simd` 和 `simd/archsimd` 均为编译时实验。本机实编 `GOEXPERIMENT=simd`，用 `archsimd.X86.AVX2()` 检测指令集、八通道比较字典编码，并用通用循环处理尾段。与相同实验工具链下的通用版本配对，热筛选仅 5/8 变快，完整 CSV 流程仅 3/8。便携 `simd.Uint32s` 原型用同一组连续编码和掩码测试，热筛选配对增加 6.6%（仅 1/8 变快），CSV 全流程增加 2.2%（2/8）。另用基线 CSV 完整工作流的 CPU profile 训练 PGO，对最终代码的 CSV、TXT 流程分别增加 7.0% 和 7.1% 配对耗时。再用相同 CSV 训练结果验证 131072 行 TXT（训练样本的八倍），5/8 对变快，累计分配 58.50 → 65.08 MB。本轮交付沿用默认 Go 构建。原始 CPU 采样、实验覆盖文件与探针在 `validation/1.20.2/private/cpu-engine/`。[AVX2 对照](../../validation/1.20.2/cpu-engine/avx2.json) · [便携 SIMD 对照](../../validation/1.20.2/cpu-engine/portable-simd.json) · [最终 PGO 对照](../../validation/1.20.2/cpu-engine/final-pgo.json) · [PGO 独立规模复测](../../validation/1.20.2/cpu-engine/pgo-holdout.json) · [Go 1.27 发布说明](https://go.dev/doc/go1.27) · [Go PGO 指南](https://go.dev/doc/pgo)
