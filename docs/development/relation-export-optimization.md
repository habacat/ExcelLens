# 关联导出性能与存储优化

当前工作状态统一见[实施待办](improvement-progress.md#接续入口)。只读功能已收尾，本包只改进已有完整关联提取，不扩大源格式或容量，不修改源文件。

## 现有证据与方案评估

历史真实百万关联导出输出640,779,406字节。该收据只证明当时版本；当前实现仍逐行写两侧完整来源身份和JSON状态，需重新测量后才报告优化收益。

候选方案：

1. 将重复元数据编码限制在每次导出的有界缓存内；以完整源类型/存在/缺缓存/类型丢失/截断/读取状态为身份，碰撞必须逐字段核对，不能错误复用。原值、状态、原坐标、CSV列序和默认文字保护保持。
2. 复用现有ZIP CSV导出语义，以标准流式压缩消除重复字节，归档内CSV与单独CSV逐字节一致；保留单CSV选项。不先写一份巨大CSV再压缩，不引入自定义追溯格式或必须由ExcelLens解码的新协议。
3. 先比较未压缩及压缩级别的真实成本，再决定默认与界面；失败/取消仍由公共导出中心回收，完整归档关闭且同步后才发布。

## 验证状态

已取得序列化基线：同机各3次，2列重复状态中位约7240ns/记录、2273B/记录、72次分配；64列约52585ns/记录、22181B/记录、75次分配。多样状态另单列保存，不以理想重复状态代表全部资料。

10万完整合成行压缩基线的逻辑CSV为73,867,266字节，标准DEFLATE级别1归档1,255,184字节；级别3为1,203,152字节、默认级别为1,168,086字节。各次逻辑CSV SHA256相同；本机观测级别1写出约982ms、未压缩1218ms，级别3/默认约1012/1113ms。这是单次合成写出观测，不是整应用速度或峰值内存结论。

实施方案：序列化采用每侧有界状态编码缓存及复用记录槽，命中仍完整核对状态；标准ZIP采用级别1流式压缩，保留原CSV完整字节与选项，避免另造追溯协议。实现和下述自动化验证均已完成。首次测量夹具的Close签名及Record指针编译问题已纠正，未改生产语义。

CSV编码复用已实现：每写出器共享最多64项/256KiB保守费用的类型/状态编码，签名只作索引，命中逐格核对，碰撞和超限按真实状态重新编码；复用记录槽每次返回前清空源文字引用。既有及新容量/碰撞/空侧/保护定向通过。最终同命令3次基准对比的2列重复状态中位2148ns，64列26036ns；多样状态各3352/35812ns。此处仅序列化基准改善，不宣称整个关联查询同比提速。流式ZIP及服务/界面均已接通。

实际百万CSV及完整BIFF已PASS：1,000,001条关联结果的CSV为640,779,406字节，标准ZIP为12,475,411字节；65,536条BIFF结果分别40,534,438/845,249字节。两份输出各自逐行核对原值、原坐标、类型/缺失侧、重复配对原序和匹配数，并以整流SHA256和标准ZIP CRC证明压缩前后完整字节相同；源哈希未变、最后预算和查询文件归还。这里约98%的体积节省只针对这两种实测样例，不保证任意资料的压缩比。

状态模糊测试最终90,503次PASS；三包新旧专项、50项界面相关及优化后合成完整行测量均PASS，后者全部级别的逻辑CSV SHA256也与基线一致。首次浏览器核对错误地假定CSV使用CRLF，已按既有LF输出修正断言，最终流程通过。

标准ZIP64边界实际流式写入并解压4,294,967,297字节，整流SHA256、64位长度和CRC均一致，无未压缩中间文件。此项证明4GiB以上字节流，不称作十亿真实源记录测试。

实际浏览器两组及原关联10组兼容PASS，包含原生小表和100,005记录实际CSV、5份新下载、标准ZIP独立解压/CRC及完整CSV字节比较、原文字保护/原文、实际ZIP进度格式、注入阈值推荐和用户选择保留、420px/深色与资源/源哈希。四张新截图已在接续时逐张复核；所有新下载使用独立临时目录，未读旧下载充数。最终完整标准503项JS、完整竞态七步及Linux纯Go编译均PASS，新补七模式及空结果检查已包含。60次负对照定位到两次独立导出的清单时间跨秒差异；只修正F21测试，先核对实际时间窗再严格比较其他全部字段/成员，修复后60次竞态PASS，没有改动生产恢复/导出语义。
