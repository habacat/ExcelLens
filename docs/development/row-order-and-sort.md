# 第二阶段行序与排序

本包历史验证使用当时的1.8.18版本；当前开发版本和候选状态只见实施待办。双表对账、命名视图和分析方案的当前状态见[实施清单](improvement-progress.md)。

## 设计与真实边界

- 源值、类型、源坐标和源文件只读语义保持不变。`RowOrder`描述源索引记录位置；连续结果不展开，小结果保存紧凑整数，大结果校验后映射。请求和导出独立持有引用，清除视图不使已经开始的导出失效。
- 小结果在内存中排序；大结果将比较键按工作预算分段写入`ELSORT01`，经有界归并输出`RowOrder`。正向、反向定位不是整表Go map。源缓存编码没有变化，排序段仅用于本进程查询，不用于跨进程恢复结果。
- 工作预算由`formats`维护：排序比较键及归并头64MiB；全部活跃排序段与保留行序共享进程内8GiB和8192文件。字符串分配余量、数组扩容旧新载荷、归并双缓冲及I/O余量分别计费；文件扇入按头长度进一步收紧，最多16个输入。源索引映射、列缓存、行解码及整个Go进程不属于这64MiB上限。
- 单行排序键可能包含超长原文及折叠文本。超过可归并上限时明确拒绝，不截短比较键。磁盘写入、损坏、截断、重复位置、取消和预算错误均不发布部分结果。已有结果保持可读。
- 数值、文本、空值分类及精确十进制/百分比比较共用原规则。自然顺序是用户明确选择的文本模式，数字段任意长度均不经整数或浮点转换；源编号的前导零保留，等值数字段继续比较后缀，完全并列按源顺序。
- 结果文件登记和清理共锁；文件名携带PID，其他活跃进程即使已关闭排序段句柄也不被误删。系统无法确定进程状态时保守保留，PID复用可能延迟旧文件回收。此保护不等于跨进程共享磁盘配额。
- 顺序扫描采用1MiB正向或反向窗口；分散跳转先取16KiB对齐窗口。解码仍以原索引的精确记录边界为准。

## 验证

专项测试覆盖小预算强制多轮归并与内存结果一致、五级键、精确大数/百分数、Unicode/空值、超长数字段、稳定并列、源格定位、映射引用、损坏/截断/超长编码、取消、输出失败、预算不足及跨进程清理。跨进程回归使用自有子进程持有已关闭句柄的排序段，活跃时保留，退出后回收。

完整标准检查及竞态检查通过，包含190项前端回归；Linux工作簿测试二进制交叉编译通过，未在Linux执行。原有17组隔离浏览器恢复与分析流程仍通过，分别见分析安全和恢复与异常。

500万零1行、5列合成CSV沿实际适配器、筛选、排序、行序和导出链路验证：

| 检查 | 范围与断言 |
| --- | --- |
| 全量筛选 | 5,000,002条含表头，逐位置核对；连续区间没有结果文件 |
| 稀疏筛选 | 2,142,858条数据加表头，逐源位置核对，无200万条截断 |
| 单列及五列排序 | 两次均逐位置核对全部结果；稀疏反向定位样本及引用释放后继续读取 |
| 完整CSV导出 | 逐条核对顺序、金额原文及前导零编号，不以首尾样例代替完整核对 |
| 扫描及归并取消 | 返回真实取消状态和空结果，临时文件全部回收 |

来源及采样收据见规模验证。排序首键为唯一倒序整数，五列路径同时预计算金额、自然文本、分类和编号；大规模样本不替代多级并列比较专项回归。生成数据可能重用已有索引缓存，打开阶段不作冷启动耗时结论。100ms采样的Go堆不含映射及系统文件缓存，临时文件采样可能漏过短暂峰值，均不是严格进程峰值。

30万零1行同类合成场景中，发现正向预读使倒序CSV导出反复读大块；观察到修复前39.135秒、修复后0.459秒。此为各一次仪器采样观察，不是多轮中位数或普遍提速承诺，后者逐条导出核对通过。

隔离Chrome使用真实服务及262,145条数据验证自然排序、冻结行不重复、源行定位、实际拖选和Ctrl+C，以及关闭导出窗口并清除筛选后的完整下载内容。下载结果固定显示创建时的来源和范围；完整筛选导出行数包含冻结行，不能拿滚动正文行数代替。见浏览器收据。它不等于桌面人工或Office/WPS验收，也没有十亿条记录实测。
