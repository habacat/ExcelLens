# 多表追加与字段对齐

F17来源准备、定义目录、分析接入及字段对齐界面已完成源码及自动化收尾。最终代码联合浏览器7组、实际XFD/百万2组、既有单表兼容、完整标准及Go竞态七步/422项JS全部PASS。未提交、发布或进行桌面/Office/WPS人工验收；当前状态与下一动作见[实施待办](improvement-progress.md#接续入口)。

## 来源和字段契约

`sourceview.Append`版本1保存有序来源、结果字段及逐来源显式列映射，不复制原表正文。`TableRef`包含内容及路径身份、工作表、表头、来源版本和可选范围规则；只描述已经打开的来源，不授权按配置中的任意路径读取文件。相同内容的不同路径不能交换追溯关系。

每个结果字段在每份来源中映射到一个真实列，或显式选择空列。缺列不等于源空字符串；结果缺列、源格不存在、源格存在但为空分别保留。输出字段必须有来源；重复来源、重复列绑定、未知版本、源范围错配和超容量均拒绝，不靠位置、相似名称或看似金额的原文猜测对齐。

来源固定、索引、HTTP任务、持久化、界面与最终发布由server负责。`composition`只负责绑定已核对的源描述、按需投影和顺序流式追加；公共适配器继续提供`Workbook`和`CellData`，不为格式另建读值逻辑。分析表保留现有文字语义，不扩展为源文件编辑。

## 值与追溯

结果记录同时保存唯一追加序号、来源槽位、真实源行和源索引位置；每格另保存结果列、真实源列及原始`CellData`。不把联合行号或字段顺序写入`CellData.Ref/Col`。金额精度、源文字、前导零、公式缺缓存/不可还原状态、错误、样式引用及呈现元数据保持原有含义。

扫描只向每份来源请求当前操作需要的列；投影全为缺列时只遍历行引用，不随意读取某个未选中的大值。按行回调借用当前记录和呈现对象，消费者若需保留预览必须复制并执行自己的总字节预算。核心每次扫描只保留有界列映射和一行输出，不缓存完整数列或整张联合表。

完整扫描在前后分别核对所有来源；行数不符、取消、源变更、读取/消费者失败都不能发布完整结果。消费者只能在整个扫描成功后原子发布完整导出。有限预览允许显式提前停止，但只发布已经复制的完整行，另核对所有来源并返回`previewTruncated`；索引确定的总记录数不等于预览已经逐格验证全部记录。

## 工程边界和验证

来源数量、输出列数、配置/请求/单行文字、预览、任务历史和跨标签保留容量由`formats/composition.go`统一维护，不改变任何格式的原容量。输入配置、源描述/分析表快照及响应字节都有所有权预算，源快照直到最后借用者关闭才退还；这不是整个进程、原有缓存、每个聚合结果或系统文件缓存的总内存上限。版本1定义独立于源值/行索引/布局缓存；联合查询另以工作区版本6拒绝旧应用静默忽略新语义。

底层为`sourceview/append.go`及`composition/append.go`；`server/composition_source.go`接公共适配器、来源固定、独立引用及按列流式读取，界面从分析工作区“多表追加”进入。原始表头匹配由`sourceview/headers.go`统一，分析方案保留原有类型兼容守卫；名称相同但原始表头不同、截断、重名或无法证明完整唯一时不自动绑定。

默认定向已覆盖OOXML、CSV、TSV、TXT、HTML-XLS、BIFF8及Windows SQLite/GB18030，包含源行缺索引、取消/关闭独立引用、失败回收及分析表内容版本。源表头和正文在读取前检查现有行描述字节预算，零列投影只遍历引用。当前验证收据与未完成项见待办；后续完整检查不能由早期收据代替。

初期空切片/nil、OOXML缺省数值类型及公式前导等号的测试断言已按公共读取语义纠正；没有为通过测试而改写源类型或表达式。来源断言的原始失败结果保存在版本验证目录。实际百万CSV/完整BIFF及并发引用已通过：CSV全量1,000,000行逐值/坐标核对，追加后1,000,002行；BIFF物理65,536行（其中首行选为表头），追加后65,537行，末行及全部原值类型已核对。采样Go堆仅为该测试进程的观测，不含映射/系统文件缓存，也不据此宣称产品普遍提速。

捕获发布前另核对来源和取消；底层工作包当时的完整标准及Go竞态七步/405项前端PASS，规模复核亦通过。后续任务/预算/槽所有权已修改公共实现，该历史结果不代替当前任务包检查。

## 来源准备与预览任务

`server/composition_tasks.go`提供字段准备和追加来源准备两种显式任务，`/api/composition/start`、`status`、`result`、`cancel`、`clear`分别负责启动、轻量状态、固定响应、取消和释放；`limits`直接返回formats的同一限额。来源列表及上传复用现有来源选择和普通上传链路，没有另建格式名单。

排队前在公共缓存读锁内固定全部来源；工作线程先取得共享查询槽，再取得缓存读锁。保存的筛选范围通过`restoreAnalysisSourceWithQuerySlot`借用已持查询槽，不重复申请第二个槽。保留资源的多来源任务使用明确的`compositionTask`所有权状态；它与只持普通元数据的任务生命周期不同，不把含句柄的快照直接塞入会置空丢弃的旧模型。

每页面最多2个活动、4个历史及2个保留结果；所有页面共享160MiB保守计费。排队配置、源快照和响应分别收费，任务取消/失败/清除/淘汰/切档/退出均退还自身资源。借用者在App锁内取得独立来源引用；释放实际句柄/行序/预算在锁外执行，原任务移除后其分析/导出借用仍可用。保留`keepId`的旧结果不被失败的新候选替换。

`composition_preview.go`只保留最多100行及4MiB预览，公开精确文字、源类型/缓存/公式状态和真实源格坐标；追加序号单独存放。克隆保留文字，避免短字段挂住整个大源行缓冲。达到行数界限时不解码下一行；超过显示容量的单行不截断格值，可返回空预览及明确的预览受限状态，完整来源仍可供后续操作读取。任务状态为“来源已就绪”，不伪称完成整表扫描。取结果时重新核对所有真实来源，变化返回冲突。

任务包HTTP/来源定向已通过字段/追加/原始坐标、取消重试、双过滤来源并发、缓存读锁顺序、跨标签预算、宽至XFD字段、超出预览容量、移除附件仍有引用、完成发布边界取消、切档/退出及其他来源变化等回归。实际API规模另外启用门控后通过百万CSV和完整BIFF：字段/100行预览/借用来源、清除任务后完整逐值/坐标及原生BIFF类型读取、最后预算归零及源哈希不变。当时任务包完整标准/竞态七步及405项JS全部PASS。后续分析接入修改了公共拥有者及预览函数，不能用当时结果代替本包检查。

## 定义目录及分析绑定

`composition_store.go`在用户配置目录保存版本1定义目录；32份定义及8MiB文件上限由formats统一维护。`/api/composition/definitions`提供读取和显式保存/替换/删除，复用严格配置封套、校验和、逐文件锁、Sync及失败保留旧文件的替换。保存只接受成功准备任务，核对所有物理来源及分析表内容版本；确认丢失后，同一捕获ID可在任务清除或进程重开后重试，不能以同一请求替换不同内容。跨页修改需预期目录修订号；损坏、未知版本、重复绑定及同名定义拒绝，不重置目录。

联合查询使用`source=append:<规范定义摘要>`及可选`composition`声明；从准备任务运行时，可用顶层`sourceId`传其任务ID，服务端取得规范定义并写入最终Query。报表始终保存完整定义，运行时ID不进入Query；定义/摘要不一致、缺定义、另带单表范围或表头均拒绝。首次保存联合报表写工作区版本6，读取、备份恢复及后续保存共用校验，旧版本1～5继续兼容且新工作区不降级。源值、行索引、布局及公式缓存编码不变。

`analysis_composition.go`通过现有`analysisSourceSnapshot`独立持有联合快照，`SourceRows`不再假定只有单表行计划。排队前借用已准备来源，或只固定声明中已经打开的工作簿；后一种在执行线程取得共享查询槽后才恢复范围及字段，缓存读锁始终在查询槽之后。多个过滤来源借用同一个已持槽恢复，不二次申请；取消/失败/清除/淘汰关闭自己的引用。层级展开和异常导出各持独立引用，准备任务/根结果清除或附件移除不取消已经借出的读取；全部消费者关闭后退还来源预算。

字段预览沿用公共有界预览，只读前8条，数值资格逐格按原文件格式调用既有规则；画像和分析只投影本次需要的字段。原生Excel文本金额不参与自动数值聚合，CSV等按原有精确文本金额规则处理，分析表保持其已有文字语义。未触发日期检测、公式重算或源类型改写。完整流式扫描成功前不发布聚合；下钻/样本提前停止后也核对全部来源，未遍历来源的变化仍使本次结果失败。

`analysis.Record.Number`和下钻`row`继续表示真实源行，`sequence`单独表示联合顺序。`origin`带真实工作簿身份、文件、工作表、版本和逐输出字段的原列映射；零列表示缺绑定。明细提取分别写联合序号、来源文件/表/工作簿、源行及与输出字段对应的源列映射，再写数据；异常样本、提取和完整CSV使用真实来源文件/表及原列号，转换字段也追溯到原输入列。单表输出列顺序及语义保持原样。

分析方案捕获/重放的现有类型守卫只有单格式语义，本包明确拒绝联合来源，不伪造单表方案。联合来源可保存为报表重开；重开只绑定已打开的匹配来源，缺失、内容/分析表版本变化或范围失效均停下，不按路径偷偷打开文件，也不退回完整源表。界面接入需先准备保存定义，再取字段及运行分析，明细必须携带完成任务ID。

持久化定向、分析及生命周期定向、单槽多过滤恢复、版本兼容和实际分析规模已通过，含双向OOXML/CSV资格、精确聚合、编号/缺缓存、明细/异常/层级追溯、任务清除、取消、未访问来源变化和独立导出。规模项逐条核对1,000,002/65,537条的原行、精确值和资格，源哈希不变，清理后预算归零；本机耗时不作为普遍性能提升结论。最终完整标准/竞态七步及405项JS全部PASS，会话92033退出0，无活动检查/未处理失败或后端草稿；尚无本包新界面及浏览器专项，不代表桌面人工验收或整个F17完成。

## 共同约束

界面工作包采用现有分析工作区的`#f6f8fa`底、`#ffffff`控件面、`#223344`正文、`#136c70`操作色和`#e5eaf0`分隔线，沿用Segoe UI/微软雅黑及现有13px控件字号。布局以文件/工作表选择、对齐矩阵和有限预览为主体，不另做装饰卡片或说明区；内容左对齐。来源按容器换行，矩阵/预览只在自己的区域横向滚动，字段分页和共用搜索选择器避免宽源表造成大量DOM。窄窗口保留同一字号和完整操作，必要状态/失败明确显示；容器缩放不发起读取。该设计是在已有桌面工具中的字段操作，不加入营销页式标题、动画或新色板。
