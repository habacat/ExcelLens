# ExcelLens 1.20.3

在大型台账里按中文或编号搜索时，程序可以在构造单元格前排除未命中项。对已有列缓存重新筛选时，文本条件按字典值判定，再成批匹配源行。精确交叉汇总复用各分组的精确总和、计数和极值，去重容量仍在读到超限记录时立即检查。管道分隔 TXT 减少了逐行分配，工作表 XML 和可见行位图的读取也有改进。

### 大型样本结果

| 同机四对测试，100 万条 CSV 明细 | 1.20.2 中位数 | 1.20.3 中位数 |
| --- | ---: | ---: |
| 全文搜索 | 2.89 秒 | 0.42 秒 |
| 缓存列换条件筛选并读回 | 0.54 秒 | 0.06 秒 |
| 六指标交叉汇总 | 7.76 秒 | 5.30 秒 |
| 上传、索引、搜索、两次筛选和汇总全流程 | 14.15 秒 | 8.66 秒 |
| 进程峰值工作集 | 222.46 MB | 236.45 MB |

每轮使用相同输入、新服务及空缓存。源行号、前导零编号、超出浮点精度的原始金额，以及八个分组格和各层总计的六项指标，均与独立参考值一致。四对全流程均变快，峰值工作集四对均上升。CSV 独立解析和小型 XLSX 完整打开流程的专项测量没有稳定提速。[版本验证](../../validation/1.20.3/workflow-verification.json)

另做四对分阶段内存测量。建索引后的峰值均约为 223 MB，差异出现在随后的全文搜索。搜索完成时两版 Go 已分配堆均约 4 MB，但新版发生的垃圾回收较少，操作系统驻留的页更多。全部任务结束并显式回收后，两版存活堆均约 12.6 MB。峰值工作集需要按上表为大型文件预留空间。[分阶段内存](../../validation/1.20.3/million-ledger-memory.json)

五百万条合成明细通过冷建、缓存重开、表尾搜索、筛选、稳定排序、分组计数和完整流式导出。真实大型 XLSM 与 TXT 在新旧版本上的全部行偏移、共享公式锚点及 64 行抽样单元格摘要逐一相符。Windows x64 继续以纯 Go 单文件运行，由标准库在运行时选择适用的指令路径。[专项方法](../development/reading-benchmarks.md#cpu-与数据引擎配对基准)
