# ExcelLens 支持格式与边界

当前版本的格式能力和容量由 `internal/formats` 统一定义，所有文件入口共用。原生 Excel 工作簿中的文本数字不自动参与金额统计。文本、HTML 与 SQLite 按各自的精确金额规则处理，保留源类型和原值。XLSX 原公式导出需要可可靠还原的公式，公式无法解释时可使用已保存的结果。

CSV、TSV 和通过结构预检的 XLSX、XLSM 可以生成编辑副本。含宏台账按 XLSM 保存，文件内的 VBA、受支持的按钮和外部链接随副本保留。ExcelLens 编辑时只处理本地单元格。 [编辑副本](editing.md)

**OpenDocument 电子表格（.ods）** 可从常用打开入口、上传或压缩包成员只读打开。重复行和重复列按区间索引，保留源坐标、类型、显式日期、显示文字、合并和显隐信息。数值按来源原文读取，文本编号保留前导零。公式栏显示文件保存的 OpenFormula 原文，缺失缓存时明确标识。可搜索、筛选和导出；转成 XLSX 时选择缓存值或显示值。按缓存值导出保留显式日期、布尔值和文本编号，缺少公式结果时会指出源格。JSONL 可同时保留 OpenFormula 原文和缺缓存状态。原生样式、图形、计算和编辑暂不在 ODS 适配范围。

**Excel 二进制工作簿（.xlsb）** 使用纯 Go 读取 BIFF12，支持多表、共享字符串、公式及其缓存、样式、富文本、合并、冻结和显隐。批注、链接、嵌入图片、命名区域、条件格式规则、验证和打印设置使用工作簿原有查看入口。可搜索、筛选、排序、统计、分析、对账和导出。公式栏显示从二进制令牌还原的表达式，遇到无法还原的公式会标明原因并保留已保存的值。文件支持离线只读打开。[样式、公式与界面覆盖矩阵](../development/xlsb-compatibility.md)

## 在线数据库

从「打开 → 在线数据库」或首页右上角的圆圈感叹号进入「连接在线数据库」。选择数据库类型，填写域名或 IP、端口、账户及需要的数据库名。Oracle 和 ClickHouse 可切换连接方式，其他数据库自动使用对应协议。默认使用验证服务器证书的 TLS，私有 CA 可上传 PEM 证书。端口留空时使用当前连接方式和传输安全的默认值。

| 数据库 | 协议 |
| --- | --- |
| MySQL、MariaDB | MySQL 协议 |
| PostgreSQL | PostgreSQL 协议 |
| Oracle | Oracle Net 服务名或 SID |
| SQL Server | TDS 用户名和密码 |
| ClickHouse | Native 或 HTTP／HTTPS |

点「读取目录」后可按表名或架构查找，一次可打开最多 32 张表或视图。点击「保存并打开」会把本次结果保存为独立快照。首行为数据库字段，之后按本次服务器返回顺序提供稳定的本地行号。每张表分别查询，快照记录各表读取的起止时间和未指定排序的口径。多表工作区提示「各表独立采集」。可按工作表筛选、排序、搜索、统计、分析、对账和导出。获取更新的数据时，重新连接并读取会产生新的快照。

### 保存、核验和迁移快照

首页右上角圆圈感叹号和工作区「打开」菜单都能进入「数据库快照」。列表显示本机快照目录总占用，可按来源、表名、采集日期和容量组合筛选。可选的累计容量和复核天数只触发提醒。一次采集上限为 8 GiB。快照纳入「本地数据」的备份与迁入，支持口令加密。旧版快照点击「保存」后生成独立的固化副本，摘要从固化时起生效。

点击「删除」查看引用。应用会检查打开的页面、后台任务、可恢复的审计任务、对账结果、分析方案和本地工作成果。有引用或读取引用记录失败时会保留快照。确认删除前会重新检查。应用外另存的底稿由使用者核对。中断的采集在下次启动时依据所有权标记及文件锁回收；旧版无标记的暂存会列出位置和占用，供关闭采集程序后人工核对。

点击「核验详情」查看连接来源、采集和核验时间。选择数据表可查看 SQL、排序口径、记录数、字段定义及行文件和索引的 SHA-256。点击「导出 JSON」会重新核验，导出的原始清单文件可独立计算 SHA-256，与页面的清单摘要比对。新采集和新迁入的快照文件设置只读。网格读取会检查当前表部件的版本，发生变化时重新核验。文件系统缺少可靠修订号时，快速检测取决于可用的文件身份与时间信息，显式核验仍检查完整内容。

连接界面关闭后会清除密码和 CA 证书。企业环境应使用具备最小 SELECT 权限的专用账号，优先连接报表库或只读副本。`NULL` 与空文本分别保留，数据库精确数值保留十进制原值，二进制以十六进制读取。未知类型或超限时会报告失败并保留当前工作簿。

XLSX 编辑模式可在当前修订内计算本簿单元格、固定名称及范围引用。SUM 和 AVERAGE 支持多个区域，录入公式时会保留目标已有数字格式，常规目标按公式及其引用选择显示格式。即时计算索引最多覆盖 50 万个非空源格、100 万个引用和 16 MiB 公式原文。单次修订限制求值访问量及结果大小；超过容量时，可保留编辑并在生成件中交由 Excel 重算。 [计算与文件边界](../development/xlsx-grid-editing.md)

XLSX 可以含 ZIP 空目录项、静态自定义属性、打印区域、重复标题和可解析的本簿定义名称。在编辑副本中，可逐格改值或公式，在空白地址输入，插删或移动完整行列，以及重命名工作表。本簿固定来源的透视表支持多层行列、多个值字段以及分页、标签、值和日期筛选，刷新时重算小计和总计。本簿普通图表可更新单行或单列序列。透视结果、数组范围、合并及表格字段有各自的变更规则。 [操作与支持范围](editing.md)

## 原生数据读取架构

普通工作表中的 Excel 表格对象按其范围和列定义编辑。仅在确认格内输入时扩展计算列。结构化引用使用原表名和字段，数据、汇总和跨表结果随修订重算。受保护工作表按有效的单元格、行或列样式区分锁定状态。工作表关系、原保护记录和样式随编辑副本保留。连接查询表和 XML 映射表在预检时会提示其结构限制。 [第七阶段编辑说明](editing.md#编辑-excel-表格和保护表)

- Excel 2007+：`.xlsx` / `.xlsm` 继续以 OOXML ZIP/XML 逐 Sheet 建索引，遵守 Excel 原生单表 1,048,576 行、16,384 列。
- Excel 97–2003：`.xls` 使用纯 Go 自研 OLE2/CFB、MiniStream、BIFF8 解析器，**不执行 Office 转换、宏或公式计算**。BIFF8 的物理上限是 65,536 行、256 列。
- Office/WPS/Oracle HTML XLS：按文件内容识别 `.xls` 中的 HTML 文档；同一文档的多段顶层表格、标题与段落属于同一个工作表，只有明确的 Office 工作表声明才分表。保留段落空行、实体、显式换行及 rowspan/colspan 后的源坐标，主网格和冻结窗格读取同一组合并范围。沿用外部数据行数规则，不套用 BIFF8 的 65,536 行限制。常见字体、字号、文字/背景色、对齐、加粗和边框包含内部 `p/span/b` 标签继承及分项边框。只静态识别 `="字面量"` 的已知缓存值并保留表达式，不运行其他公式或脚本、不加载外部资源。复杂 CSS、混合富文本、Excel 自动列宽/行高、图表和超大合并范围的完整视觉还原不保证；筛选/排序及跨冻结边界的合并按源坐标分格显示。嵌套/不完整表格或无法可靠对应的多 Sheet 声明明确报错。
- 外部数据：`.csv`、`.tsv`、`.txt`、`.db`、`.sqlite`、`.sqlite3` 直接逐行解析到专用 **ELNROW02 二进制缓存**；保存实际行偏移供滚动/筛选/搜索随机读取。它不是 Excel 文件，更不使用 Excel 单表行数上限。
- 外部数据单表容量上限为 1,000,000,000 行，实际可处理规模仍取决于内容、内存、磁盘和耗时。列宽不代表 Excel 的业务列；当前 UI 最多呈现 16,384 列。每字段最多 8 MiB，每行最多 128 MiB。打开/索引不静默截断，超过限制时报错。SQLite 的首条字段名记录也计入此行数上限。
- 浏览器本机上传上限为1 TiB；文件选择、源格式容量和界面输入均使用统一配置。超大文件建议通过右键菜单或 `ExcelLens.exe "数据文件完整路径"` 直接只读打开，避免浏览器上传副本。压缩包成员、容器和单元格内容仍有各自的字节限制，见下文。

## OOXML富文本

XLSX/XLSM的共享及内联文字保留已解析的片段字体、颜色、字号、粗斜体、删除线、下划线和上下标，主网格、冻结、HTML复制及HTML/XLSX快照共用。原始文字、源类型和坐标不因样式而改变。普通统计/筛选不解码字体；原生文本金额仍是文本。

未知字体效果、损坏或容量限制保留原文并提示；单格详情也可查看原因。会计下划线在浏览器及HTML中近似显示。带格式XLSX遇到不完整片段会失败，可关闭原始格式后导出完整原值。每格最多4,096个样式片段，主网格与全部冻结窗格分别最多8,192个；超限只减少样式，不截断原文。Office/WPS视觉对照和桌面人工验收未进行。

阅读页按选区大小选择复制方式。带格式复制最多 250 行、50 列、5,000 格，原文、显示文字与公式合计 4 MiB，HTML 输出最多 16 MiB。超出时改复制 TSV 显示值，最多 2,000 行、200 列、50,000 格，转义后的文字最多 4 MiB。再超出时会打开选区导出，可选择格式后保存。[复制与粘贴](clipboard.md)

## OOXML条件格式

XLSX/XLSM的常见数值比较、同表绝对和相对引用、算术与逻辑表达式、文本/空白/错误条件由主网格、冻结、带格式复制和HTML快照共用。只计算当前请求的范围；原始数值、文本编号、类型、样式编号和坐标不改写，仅有显示效果的空白格不增加数据记录或已用区域。条件数字格式的显示文字与源值分开，关闭“原格式”可查看原有显示结果。

表达式支持 IF、AND、ROUND、DATE、WEEKDAY、SEARCH，以及 SUM、COUNTIF、SUMIFS、MATCH 等有界范围计算。整列引用使用索引定位已有行。日期沿用工作簿的 1900 或 1904 系统。工作表级和工作簿级名称可引用本表或其他表的固定绝对单元格，局部名称优先。动态或外部名称、其他未能还原的跨表表达式、超出计算容量或缺少缓存时，单格详情显示原因，并保留源值。

固定单列的 COUNTIF／COUNTIFS、SUMIF／SUMIFS 及精确 MATCH 可建立共享统计索引。条件计数和求和中的固定通配符或比较条件可在建索引时过滤，逐格变化的等值条件按键查询。纵向滚动 SUM 复用前缀和。对于不能直接做二进制精确减法的窗口，按源顺序复核已索引的数值。大表在打开工作表的索引进度中显示此阶段，可取消。重新打开同一版本的原件可复用磁盘统计，清理工作簿缓存后按需重建。

每张表最多准备 24 个统计方案，每个分组方案最多 8 个匹配字段，统计文件上限为 512 MiB。动态通配符、近似查找、多列矩形、索引不可用或超出方案容量时会尝试有界求值。条件公式的加减乘除、顺序求和与结果比较已用 Excel 精度样例验证，显示和导出的源值保留原始精度。

需要整表统计的规则、色阶、数据条、图标集、复杂表达式等尚未完整还原；缺少公式结果、未读引用或超出显示容量会保留原因，不用零或默认颜色替代。可悬停或打开单格详情查看。会计下划线近似显示，条件文字旋转尚未显示。

带格式XLSX可把已证明的当前效果冻结为普通样式，支持排序、选区和多表快照；富文本的条件字体也同步保留。它保存当前效果，不携带继续变化的条件规则。遇到未确定规则、缺少所需公式结果、损坏或样式容量不足时仍会失败，不提供部分下载；可选择带说明的HTML，或关闭原格式后导出。

常见小数、千分位、百分比和会计格式按源十进制计算显示，保留大数尾数并正确处理1.005等舍入边界；原值和类型不变，不自动解释文本编号或转换文本日期。普通整格字体支持上下标、双下划线及明确的源样式继承。Office/WPS视觉对照和桌面人工验收未进行，实际实施和验证状态见[实施清单](../development/improvement-progress.md)。

“行与大纲”提供原始显隐、显示全部、源行范围显示/隐藏、组展开/折叠和按层级展开；主网格、冻结、方向键、复制及选区统计共享可见行。定位到隐藏源行时临时显示，不覆盖已保存偏好；源文件和源行号不变。导出明确区分“当前可见行”与包含手动隐藏行的“完整筛选结果”。操作与恢复边界见[行与大纲](row-visibility.md)，实际验证状态见[实施清单](../development/improvement-progress.md)。

## 数据规则

XLSX/XLSM普通及x14规则、BIFF8 DVal/Dv/CONTINUE按需读取，提供当前格/全表只读查看、条件和提示、可靠文字列表及源区域定位。不会在打开、索引或滚动时扫描规则，也不执行源验证公式。未知结构、范围、引用列表和读取失败保留真实状态，不当作没有规则或验证通过。规则写入、下拉选值修改及整表校验未开放，详见[使用说明](data-rules.md)和[实施记录](../development/data-rules.md)。

## 超大数据模式

按实际索引记录数判断，超过500万条自动启用超大数据模式；仅尾部行号很大的稀疏表不会因此关闭功能。状态栏显示模式名称及限制说明，实际验证见[实施清单](../development/improvement-progress.md)。

- 保留视口查看、普通滚动、冻结、地址框、Ctrl+Home / Ctrl+End、搜索、条件筛选、多级排序、精确计算及 CSV/TSV/JSONL/ZIP CSV 流式导出。XLSX和带格式HTML目标继续遵守各自的输出限制。
- 关闭纵向 Ctrl+方向键全列扫描；横向单行跳转可用。查重须选择不超过500万行的单列区域，并保留既有不同值与内存预算。界面入口和后端均校验，不会先扫描后再阻止。
- 条件筛选和排序可扫描完整源表，结果不再以200万条截断。结果行序按需落盘；排序比较键受64MiB工作预算约束，超过后分段归并，单行比较键过长时明确拒绝。所有进行中的排序段和保留结果共用进程内8GiB、8192个临时文件预算，预算或实际磁盘不足均不发布部分结果，已有视图保持有效。该工作预算不是整个进程的内存上限。
- 选区统计仍限400万格、定位检查仍限1200万格，公式引用仍限400万格。范围先校验再分配行号；筛选后的计算仅收集选中行，不按整张大表分配位图。
- 在用大索引采用只读文件映射，Windows不能在线删除对应文件。打开期间拒绝清理这些缓存；退出程序后再清理。查询保留自己的索引快照，后台回收不会释放仍在使用的映射。
- 行索引超过262,144条后分批写盘并只读映射，Go堆中不再为每行长期保留24字节的结构。索引文件仍约20字节/条，十亿条约需20 GB索引磁盘，另加原文件和行缓存；映射虚拟地址、操作系统文件缓存与Go堆是不同的资源。完整搜索、筛选和导出仍需顺序读取数据，不能保证任意文件均可即时完成。

开发树已逐项核对500万零1行、5列合成CSV的全量及稀疏筛选、单列及五列排序、完整排序导出与取消，见[行序和排序验证](../development/row-order-and-sort.md)。这些证据不代表十亿条记录实测、任意文件的即时完成或桌面人工验收。

## XLS（BIFF8）准确性与范围

- 支持 OLE2 FAT 与 MiniFAT 小数据流、Workbook/Book 数据流、BIFF8 工作表元数据、隐藏 Sheet、共享字符串与 CONTINUE 跨记录、Unicode/代理对、RK/MULRK/NUMBER、BOOLERR、LABEL/LABELSST、普通公式及缓存结果。
- 支持 BIFF8 XF 常见数字格式、日期系统、默认及自定义索引调色板、字体与常见边框；隐藏列来自 COLINFO。公式栏仅在可确定语义时还原公式令牌；无法确定的令牌或引用以明确文本提示，不会重算缓存。
- 内嵌图表子流不会提前结束源值读取；可确定的公式引用按源坐标与相对偏移还原，BIFF行索引使用`biff3`缓存命名空间，旧行索引按需重建，源公式缓存值不重算。名称及普通/XML映射/查询表目录提供只读查看，Web提供程序列和合计数组公式附加数据明确保留未支持状态；详见[实施记录](../development/catalogue.md)。
- **尚不保证** BIFF2–7、加密 XLS、数据透视表对象、VBA、图片/图表、评论、形状、外部工作簿引用、复杂共享/数组公式或完全一致的合并格显示。对这些特殊格式不能承诺与 Microsoft Excel 像素级相同。
- 长银行账号要核实存储方式：原始字符串及单元格自定义显示格式会尽量保留；如果 XLS 内部本就把超过 15 位的账号保存为浮点数，解析器**不能恢复 Excel 已经损失的有效位**。

## Oracle 导出的 TXT / CSV 与编码

1. 自动识别 UTF-8（含 BOM）、UTF-16 LE/BE（含无 BOM 判断）、Windows GB18030/GBK。为降低错误解码的风险，无法确定的编码会提示核验。
2. 识别 Tab、竖线、逗号、分号、`@` 分隔。CSV 支持被引号包围的分隔符与换行；Oracle 凭证 TXT 通过“凭证来源、批名、凭证编号……segmentN、segN_desc”完整字段结构识别，按字面处理原文引号，保留中间及末尾的空列。记录列数异常会报错，避免金额列静默错位。
3. SQL*Plus 常见定宽账表支持“标题 → 由 `----` 等构成的分隔行 → 数据”结构，跳过识别到的重复表头/分页符。复杂定制报表仍应以原账表的字段、行数、借贷合计交叉核对。
4. 任何外部文本 `=SUM(...)` 等值不会作为脚本执行，输入账号 `0000123456789` 不会自动转为数字。精确金额统计不修改原有可见文本。
5. 对表头与首条数据缺少换行的 Oracle 凭证导出，只有完整字段名、`segmentN/segN_desc` 序列、双倍减一的列数关系及至少两条后续完整记录共同确认时，才在读取时拆成“表头 + 首条数据”；文件信息中注明此处理，源文件保持原样。旧版文本索引指纹已更新，避免复用错误分列的缓存。
6. TXT 使用同一解析器在已读取的样本中识别表头：Oracle 凭证/SQL*Plus 使用已确认结构，普通分隔文本结合字段名、列数稳定性和后续数值/日期特征判断；只读最多 12 条样本记录，不新增全文件扫描。不确定时维持普通视图。识别只影响界面，不删除首行、不改列名/类型或源行号。
7. 识别后，源表头仍可见或已冻结时，顶部只显示列字母，由源表头提供字段名和筛选菜单；源表头完全滚离后，顶部固定显示「列字母 + 字段名 + 筛选菜单」，滚回时恢复，避免同屏重复。完整索引前筛选按钮禁用。顶部的「表头」可手动指定源行号或切回普通文本；调整表头会清除当前筛选/排序，避免旧条件套在新表头上。当前设置保留在本标签页会话，重新打开文件会重新自动识别。

## SQLite 只读数据库

- Windows 10/11 使用内置 `winsqlite3.dll`，通过只读打开和预编译查询读取表与视图，首行为 SQL 字段名；不提供 SQL 编辑器或写入接口，不依赖第三方驱动/CGO。
- `NULL`、`BLOB` 使用 `[NULL]` / `[BLOB N bytes]` 查看占位，不能等同于完整数据的数据库语义或 BLOB 原始导出。
- 对于 WAL 模式，本地路径扫描会检测 WAL 修改、要求重新索引；浏览器单文件上传不包含 `-wal/-shm`，上传前须在原数据库系统完成检查点或一致性快照。
- 大型视图可能由 SQLite 数据库自行执行复杂查询，其性能及锁争用不是视图前端能保证的。

## 原生压缩包

- 支持 ZIP、7z、RAR（RAR4/RAR5）、TAR、GZ/TGZ、BZ2/TBZ/TBZ2、XZ/TXZ，含 `.tar.gz/.tar.bz2/.tar.xz`。随程序内置解码器，可直接打开压缩包。
- ZIP、7z 和 RAR 先读目录，提供分页、搜索和键盘选择。选中的成员异步提取到按内容指纹区分的本机缓存，再交给同一工作簿引擎。压缩 TAR 先流式解码为可随机读取的容器缓存。单一 GZ/BZ2/XZ 按解压后的文件名识别数据格式。
- 最多 4 层嵌套、200,000 个成员、单成员 16 GiB，TAR 解码容器最多 64 GiB。7z 字典上限 512 MiB，RAR 字典上限 128 MiB，RAR 目录读取上限 16 MiB。7z 和 RAR 共用 2 个解码槽位。
- RAR 支持单文件普通和固实压缩包，处理加密成员或分卷时会提示先解压。固实 RAR 后部成员需要顺序解码，前置成员声明大小合计上限为 64 GiB。7z 和 RAR 的定位阶段均可取消。
- 提取核对已声明的长度和校验值，校验通过后才发布临时结果。缓存文件名由散列生成，原压缩包和成员路径保持只读。
- TAR 成员声明长度超过实际可用字节时，显示文件名及声明/现存/缺失大小，保留之前确认完整的成员；不把截断或校验失败当正常结束。对 TXT 可明确选择「仅查看现存片段」，仅支持已识别的 Oracle 凭证、SQL*Plus 定宽或单列原文；未识别的分隔文本、CSV/TSV、Excel/SQLite/嵌套压缩包不做片段恢复，避免把引号内换行或二进制片段误当完整数据。
- 片段表格只读取至最后一个完整物理行结束符，末尾未结束记录不纳入统计/导出，原始字节仍完整保留在片段缓存；完整记录继续校验编码与列数，不吞掉中间损坏。不完整提示在工作区、最近文件重开和嵌套来源中保留；片段导出文件名带「不完整片段」。文件缺失字节及尚未读到的后续成员不可凭空恢复，必须另取完整原包。TAR 稀疏成员不按连续文件开放；被截断的 SQLite WAL 会阻止相关数据库读取。
- 最近记录保存原压缩包及嵌套链，缓存被清理后重新生成；在用成员及其祖先容器会被保护。多标签页使用独立的目录、任务与工作簿状态。
- 同目录 SQLite `-wal` 成员自动一起读取，`-shm` 由 SQLite 在本机缓存重建；重复/过大的 WAL 拒绝。源压缩包必须来自一致性数据库快照，仅把不同时点的 DB/WAL 放到一起不能保证数据库一致性。单文件上传数据库仍需源系统先完成检查点。

## 首屏、排序与导出样式

[只读分页预览](printing.md)使用源打印区域、页设置、源行列顺序和显隐状态，不把画面排序/筛选或临时尺寸当成源打印设置。源能力仍由统一格式配置控制；单元格预览不等同于Office/WPS打印验收。

- CSV/TXT/HTML/SQLite 与 XLSX 可在完整索引前预览最多 80 行、40 列、约 2 MiB 内容；XLSX 读取的工作表 XML 前缀最多 16 MiB。预览按可见范围绘制，标识“完整索引建立中”，不把预览数量当成全表数量；尾部损坏仍由完整索引报错。BIFF8 首次需等待索引；HTML 表名/样式首次仍需全量扫描，之后可复用带源指纹与 SHA-256 校验的元数据缓存。
- 默认排序遵循源类型，Excel 数值按保存原值、文本编号按文本；「按显示文本」比较当前显示内容。「按数值（金额）」允许显式解释 TXT 金额、千分位、货币、括号负数和百分数（25% 等于 0.25）。近似浮点相同或百分数缩放临近时用精确十进制比较；相等值保留原顺序，非数值排在数值后，空值始终最后。字段原值不变。
- 「自然顺序（文本数字）」显式按显示文本中的连续数字段比较，例如项目2排在项目10前；不将整格改成数值。忽略文字大小写，等值数字段如2和002继续比较后缀，完全相同时保留源顺序；不解释负号、小数点或日期。
- XLSX源样式记录和theme保留；条件快照另追加去重样式，不重排源编号。XLS/HTML导出会生成有效的常见字体、填色、对齐、边框、数字格式表并保留原样式编号；这不是完整CSS或全部Excel对象的转换。保留1904日期系统、文本金额和前导零。超过XLSX原始行坐标范围的区域须紧凑输出到A1或使用文本格式。
- 行读取按批合并（最多 4 MiB），筛选扫描用 1 MiB 预读；查询列缓存以字典码保存低基数字段，超过 4,096 个不同值回退普通字符串。缓存总预算 96 MiB、单列 64 MiB，数字原值差异也计入预算。同源同表索引可去重等待，跨标签限制重任务并发。
- Windows 同一进程最多保留 64 条已完整哈希的源指纹。文件 ID、卷标识、创建/写入/变更时间、USN修订号和大小一致，且读取时能排除写入者，才复用；恢复 mtime 或替换文件会失效。程序重启、SQLite/WAL、USN查询不可用或不支持可靠文件标识的文件系统仍完整计算 SHA-256，不信任磁盘上的指纹收据；这些情况下重开大文件可能需要更长时间。USN只查询，不修改系统日志设置。

## 导出、审计安全与性能边界

- 详细分析及定位检查从当前连续选区打开时，遵循筛选、排序及冻结表头的画面范围；手动修改起止地址后按原始单元格地址分析。数值查重保留精确原值，数值、文本、布尔和错误分别比较，文本继续忽略大小写。
- 多标签共享最多两个导出槽位；排队时可以取消。临时断连保留任务，自动重试仍失败时点击「恢复查询」；切换文件会清理原任务的界面结果。
- 分析编辑表「＋10行」始终追加到已保存数据之后。单元格及批量粘贴保存失败后，草稿带下划线，并显示未保存格数及「重试保存」；版本冲突会重读已保存数据，悬停草稿可核对已保存值，再决定是否重试。当前工作簿有未保存草稿时，不能切换文件、使用页面退出按钮或导入备份；刷新及关闭页面会触发浏览器提示。草稿另有本机增量恢复副本，确认、容量及手动恢复边界见[输入恢复说明](recovery-and-issues.md)。首页恢复的其他工作簿草稿不会阻止打开对应原文件。
- 分析编辑表每格最多4000个Unicode字符，中文及emoji按字符计数；组合文字按各码点计数。批量粘贴同时受2MiB文本和编辑请求限制，超过时整次拒绝；已保留的大批草稿在点击「重试保存」时按请求预算分批。工作区持久化仍限制40MiB，超限不覆盖已有工作区。
- 打开缓存报表后，导出及生成编辑表使用该画面的结果任务；任务过期时请重新运行。图表为屏幕近似绘制，精确金额以透视表及导出为准；分数按精确值近似，缺失格不画成零。有限分类、系列及扇形正值绘制范围在图中标明。
- CSV/TSV使用CRLF分隔记录，保留单元格内部原有的CR、LF或CRLF；其他软件导入时仍可能自行标准化换行。启用文本公式保护时，按显示值导出的文本同样受到保护；显式选择保留公式文本继续保留公式。

- 大于 1,048,576 行的 TXT/CSV/SQLite 可以在 ExcelLens 浏览、筛选、搜索；完整导出优先 CSV、TSV、JSONL，XLSX 目标必须遵守 Excel 容量限制。超过上限将明确拒绝该输出组合，绝不静默裁剪。
- 文件始终只读；上传副本、索引、临时分析工作区与源文件分离。手动清除缓存前应确认未被其他标签页使用。
- 250,001 行 / 13.7 MB TSV 冷索引基准：旧 XML 索引 481 ms、缓存 87,669,925 B；新二进制行缓存索引 227 ms、缓存 17,975,065 B。环境为 Linux Go 1.23.2，CPU、磁盘、编码、字段大小改变会影响结果。
- 完整测试涵盖超 104.8 万行文本、XLS OLE 大/小流、BIFF8 共享字符串跨 CONTINUE、公式引用、调色板、隐藏列、只读源文件、缓存重开、导出链路等；Windows 平台专有 SQLite/GB18030/托盘行为须 Windows Go 1.27.3 原生验证。

## Windows 10/11 x64 构建

使用含 `vendor` 的完整源码，在项目根目录运行：

```powershell
.\upgrade-build.ps1
```

构建脚本从 `go.mod` 读取工具链版本，运行统一项目检查、vendor 离线依赖校验、Go/Node 回归、`go vet`、PE 编译信息验证、`upx --best --lzma` 压缩和 `upx -t`。UPX 须安装并在 PATH 中；`build.ps1 -UpxExe 'D:\Tools\upx.exe'` 或 `upgrade-build.ps1 -UpxExe ...` 可指定路径。SHA256SUMS 和 ZIP 使用压缩后的 EXE，所有检查通过才替换 `release`；用户持久化数据不属于清理范围。依赖许可随发行包提供；当前验证与边界见 [当前版本入口](../../README.md)。
