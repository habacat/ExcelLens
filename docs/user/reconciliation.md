# 双表对账

按 Ctrl+K 搜索“对账”，按主键核对两个只读来源中的记录及字段。

## 开始核对

1. 打开左侧数据文件，运行“双表对账”。两侧可选择同本工作簿的不同工作表、其他已打开文件，或已保存的分析编辑表。
2. 需要另一个文件时，点击“添加核对文件”。它不会替换当前工作簿；最多保留4个附加文件。压缩包先在现有入口打开所需成员，再从已打开来源选择。
3. 指定表头行并“读取字段”。0表示没有表头；编辑表使用已保存的列名和内容。相同且唯一的完整字段名可自动填入；重名、未读取或被截取的字段名需要按列字母或序号选择。
4. 核对主键和比较字段，再点击“开始核对”。最多4组主键、8组比较字段。默认不显示一致记录，可勾选“包含一致记录”。

## 核对方式

- **保留源类型**：文本、数值、布尔等分别处理，文本编号`001`不与数值`1`自动配对。数值比较和差额使用精确值。不开启日期识别，不执行源公式。
- **按显示文本**：明确按当前读取的显示文字核对，可选择去首尾空格或忽略大小写。
- **按精确数值**：明确解释所选文本字段中的数值、会计金额和百分比；百分比按实际比例处理，例如`25%`与`0.25`一致。选择此方式可能把前导零编号解释为数值，请按字段用途选择。

按精确数值核对的比较字段可填写绝对容差。留空时精确比较。差额为零计为一致，非零且绝对值小于或等于阈值计为“容差内”。单组含多个字段时，需核对优先，其次是超出容差的差异。CSV 保留全部精确差额。容差内组单独显示，跨批异常跟踪将其视为已退出异常集合。

SQLite的现有行缓存未保留原始值类型，必须明确选择文本或数值方式。`[NULL]`和`[BLOB N bytes]`可能是缓存占位，无法可靠区分与之相同的字面文字，因此不能把它们作为可信值配对。

## 结果与来源

“一致”“差异”“仅左侧”“仅右侧”“重复主键”“需核对”按主键组计数；“无效主键”按原记录计数。空键、错误值、缺少公式缓存和不可信占位不会相互配对。重复键保留两侧记录数及源行，不自动生成多对多组合。“差异”只说明读取结果不同，不代表业务错误或损失。

界面最多显示100组样例，长文字截取显示。点击源行或读取值定位原单元格；其他文件在新标签页打开。保存的编辑表定位会核对内容快照。源文件被外部修改、编辑表已变化或来源失效时，明确拒绝定位到错误内容。

修改两侧配置不会改写已有结果；界面会标明仍显示上次结果。完整CSV也使用该次结果的来源快照。外部改写源文件后，已完成结果的缓存仍固定保留，可导出原核对清单；切换主文件或退出应用会结束本页任务。

## 完整CSV与资源边界

### 比较两版工作簿

在“双表核对”选择基线和当期来源。选择“整本同名工作表”会把同名表对齐，分别列出新增或删除的表。工作表改名时可选择“所选两张工作表”手动对应。点击“比较工作簿版本”，在导出中心下载 CSV 或点击“查看差异明细”打开新的只读标签页。

明细按工作表和原坐标比较公式、缓存状态、源类型、原值及显示文字，包含两侧文件名和 SHA-256。工作表顺序、显隐、使用范围、源行记录、合并区和适配器可读取的行列布局分别列示。结构变化后仍按实际坐标逐格比较，业务主键对齐请用“双表核对”。无法还原的公式会列为待核。报告的公式形状文本有 CSV 文字保护前缀。

选择“所选两表按业务主键对齐”前，读取并确认两侧字段、表头和主键。表头后的唯一主键用于对齐业务行，表头及其上方保留原坐标比较。表中插入或删除其他记录不会将其余业务行全部列为移位。相对行序有变化时报告一组可重复的最少移位解释。重复键逐侧列出每一源行，无效键单独标记。对齐后的单元格仍按列位置比较，并列出两期源格、公式及主键。每侧支持 1,048,576 条索引记录。

### 跟踪跨批次异常

两批分别导出“全部类型”的核查包。在“双表核对”展开“跨批次异常跟踪”，选择基线与当期 ZIP，点击“比较异常明细”。程序核验包内明细 SHA-256、规则版本、主键、字段映射和文字保护方式。换列后的唯一表头仍可匹配。生成和载入都按每个压缩包 256 MB、解压明细 512 MB 校验。大批次使用磁盘排序，比较报告最多 1 GB。超限时会提示调整范围，原核查仍可导出完整 CSV。

结果按业务主键区分新增、已消失、持续但有变化和持续内容相同，并保留两期的左右源格、值、差额及组内笔数。重复组逐项保留成员，未匹配的成员单列。无效键按批次分别列出。跟踪结果说明两次导出的差异；“已消失”是否源于整改，仍需核对当期业务范围。

### 导出核查包并换批重跑

1. 选择两份台账，以编号作为主键、金额作为比较字段，选择“按精确数值”后开始核对。输入摘要在本次核对时取得。普通文件使用原始文件字节的 SHA-256，保存的分析编辑表使用列、修订及全部行的快照摘要。
2. 在结果中选“重复主键”“差异”或“全部类型”，点击“导出核查包”。ZIP 内的 `核对明细.csv` 写出所选类型的全部记录，包括来源行、源格和适用的精确差额。`核查记录.json` 保存两侧来源与表头、主键及比较字段、匹配方式、规则版本、数量、明细筛选条件、CSV 文字保护设置和明细文件的 SHA-256。核对使用表头之后的全部数据行。筛选结果类型只影响样例和核查包明细。
3. 换一批文件，选择两侧来源并读取字段。点击“载入核查记录”，选择解压出的 JSON，确认主键及比较字段后点击“开始核对”。旧版规则 1 的记录可重跑并沿用其布尔解释。新建核查使用规则 2，Excel 和 ODS 的原生布尔值按真假匹配，仍保留各自的读取原文。跨批次比较要求两期规则版本和字段容差一致。换批时按完整、唯一的表头重新绑定，列可调换顺序。同一来源快照也可按原列复用。字段缺失、重名或规则版本不兼容时会说明原因。
4. 结果显示本批各类数量及相对基线的增减。有效异常主键、分类或组内笔数有变化时也会提示，包括总数相同的情况。无效主键按源记录计数。核对具体金额和源格请查看两次导出的明细。

“导出完整CSV”进入公共导出中心，保留两侧文件、指纹、快照、表名、源行、源格、读取类型、单元格存在状态、读取值和精确差额。重复组逐条输出所有成员并附汇总；CSV不使用被截取的界面样例。默认不含一致记录，是否包含由创建结果时的设置决定。

CSV文本保护默认为开启，会保护可能被表格软件解释为公式的文字，并在读取值标题中标注。需要逐字原文时可明确关闭。CSV本身不保存Excel格式和类型，核对类型信息在独立列中保留。

两侧主键排序共享64MiB工作预算及项目统一的临时磁盘/文件数配额，超过预算明确失败，不返回截断的成功结果。每行所选字段最多8MiB、主键最多1MiB；编辑表捕获所选列，每侧最多16MiB。取消和失败会回收排序段；已有完成结果最多保留4次。清理缓存和上传副本时，活动任务及排队导出使用的来源仍受保护。

当前自动化证据和未覆盖部分见[对账实现与验证](../development/reconciliation.md)。这些检查不等于桌面人工验收。
